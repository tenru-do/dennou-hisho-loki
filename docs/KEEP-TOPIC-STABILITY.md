# KEEPとTOPIC画像観察の併用（グラスv526 / スマホv179）

## 変更の理由
従来はカメラの同時所有をCaptureLeaseで排他していたが、KEEPとTOPICがそれぞれカメラを開閉していた。撮影・暗号化保存・TOPICの画像処理が近接して走る経路があり、排他制御だけで負荷の集中は防げなかった。今回の端末ログは取得できていないため、ユーザー報告の停止原因を特定したとは扱わない。

## 今回の制御
- KEEPが動いている間、TOPICはカメラを新規に開かず、そのKEEPサービスが保存した直近写真を使用する。
- KEEPの撮影・保存とTOPIC用縮小処理は同じサービスのロックで排他する。TOPICはロック待ちをせず、KEEPが撮影待ち・処理中なら画像観察を見送る。縮小処理を開始した直後にKEEPの撮影時刻が来た場合は、その短い処理の終了を待つ。
- 保存から15秒以内、画像利用から30秒以上経過、暗号化元ファイル3MiB以内、端末がlowMemoryでなく、空きヒープに32MiB＋元ファイルの4倍の余裕がある場合だけ使用する。
- TOPICへ渡す画像は長辺640px以下、JPEG250,000バイト以下。EXIFの向きを補正し、解析用コピーのメタデータを除く。KEEPの原本は変更しない。
- KEEPの過去セッションの写真や写真未保存時の代替撮影は行わない。KEEP開始時に進行中だったTOPIC撮影はキャンセルしてカメラを閉じる。
- 音＋カメラのTOPICは、画像を見送っても取得できた音で続行する。画像のみで写真を利用できない場合はエラーや無関係なニュースの代替発話にせず、通常の再試行へ戻す。グラスには記録優先で待機中と表示する。
- GeminiへはKEEPの保存写真であることと撮影時刻を伝え、ライブ映像とは扱わせない。
