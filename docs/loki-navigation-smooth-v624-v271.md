# NAVIの動作待ち・引っかかりの調整：メガネv624・スマホv271

## 実装した6項目

1. **操作直後の反応**：経路検索に入る前に「確認中」とキャンセル操作を表示します。メガネでは大きなナビ画面が通常の状態欄を隠していても、待機中であることが見える確認画面を出します。操作受付から次のフレーム処理までの時間を測ります。
2. **最後の選択を優先**：保存ルートと通常の経路候補の両方で、古い結果を後から画面へ出さないようにしました。検索サービスとの通信中は、UIや候補全体のロックを保持しません。公開直前に現在の検索世代・案内状態を確認します。実行枠は各検索UIで最大2件、待機枠は最後の1件に制限し、同じ検索の連打をまとめます。開始確認の多重送信も防ぎます。
3. **必要な部分だけの更新**：同じ行き先、同じナビ本文は再設定せず、同じGPSサンプル・位置・方角・速度・精度なら地図カメラの再計算を省きます。新しいGPSサンプルやスタイル変更、非表示からの復帰は反映します。地図の経路線は、従来からある同一形状の再解析抑制を維持しています。
4. **経路取得と位置更新を分ける**：取得済み経路で進捗を更新する既存の方式を維持し、検索中の再取得要求は待機1件へまとめます。後から指定された目的地・移動手段・世代を残し、古い再取得要求を繰り返し積み上げません。確認画面の出発位置も、その画面自身の候補に対応したものを使います。
5. **再接続時に古い操作を再送しない**：接続失敗・復旧は状態の変化として扱い、古い待機音声と未確定の候補確認を破棄します。復旧後は現在のナビ情報を確認し直し、前の検索・開始をまとめて再送しません。メガネから送った開始要求は、応答が不明でも別の接続先へ自動で再送しません。現在の案内状態を確認する表示にします。
6. **音声の順番を整理**：方向案内の待機枠を1件にまとめ、同じ予告の重複を抑えます。待機中の重要な直前案内を、後から来た補足で上書きしません。ETAなどの補足は重要案内の後へ回します。曲がり角・経路・位置の鮮度が変わった古い案内は破棄し、待機時間を記録します。

検索のキャンセル・選び直しは、古い結果の採用を止めるものです。外部サービス側ですでに始まった問い合わせが直ちに停止する保証はありません。古い通信が終了・タイムアウトするまで次の問い合わせが待つ場合はありますが、件数を増やし続けたり、古い結果で案内を開始したりしません。

## 応答時間の確認

- スマホ：その他→ナビ→「ナビの応答時間」
- メガネ：NAV→「ナビの応答時間」

今回のプロセス起動中の直近120件までを、項目別に中央値・95%点・件数で表示します。

| 項目 | 計測する範囲 |
|---|---|
| 操作受付→次の描画機会 | ボタンの処理開始から、次のフレームコールバックまで |
| 候補・設定の確認全体 | 操作から、確認用の応答をUIへ戻すまで。ローカル設定の確認も含む |
| 経路サービスへの問い合わせ | 実際に経路サービスへ問い合わせて戻るまで |
| 画面の更新処理 | メガネのナビ表示更新処理の実行時間 |
| 画面更新の順番待ち | 受信処理からUI処理が実行されるまで |
| ナビ情報の受信間隔 | 接続待ち・切断中も含む、成功した受信同士の間隔 |
| 音声の送信待ち | 案内を待機させてから、音声送信を要求するまで |

描画機会は、画面が実際に描画完了した時刻ではありません。音声送信待ちも、実際に音が出た時刻までを測るものではありません。未計測は0msという意味ではなく、今回まだ該当する操作をしていないことを示します。アプリのプロセスが終了すると計測はリセットされます。宛先・質問本文・座標・APIキーは、この計測へ記録しません。
