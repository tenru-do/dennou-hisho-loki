# 全身モードの反応を継続して強化する

v433では対応データと会話の検証例を `tools/fullbody-scene-rules.json` に分離しました。通常のglassビルドがデータを検査してJavaを生成します。画像は264枚、既存素材は変更していません。顔モードは対象外です。

## 追加の手順

1. 実際の入力・ロキの返答・期待する反応を確認する。推測で会話の組を作らない。
2. `rules` に一意な `id`、`promptGroups`、`answerGroups`、`kind`、`intensity` を追加する。
3. `cases` にその会話例と期待する `expected` を追加する。引用・否定・第三者・医療など、似ているが反応してはいけない例も追加する。反応なしは `null`。
4. glassをビルドし、接続したAndroidで下の検証を実行する。
5. 装着したグラスで表情・動作・縮尺・発話とのタイミングを確認する。APK更新前には実機のアプリとデータをバックアップする。

各groupの中は「どれか」、group同士は「すべて」。入力と返答の両方を確認します。先に記載したルールが優先されます。`exclusions` は新しいルール共通の除外語です。既存の場面ガードと返答の分類は引き続きフォールバックとして動作します。全体の引用除去・否定処理も残ります。

`kind` は既存画像カタログの感情名（REFUSE / SURPRISE / SHY / WORRY / LISTEN など）、`intensity` は0〜3です。空の条件・不正な感情・重複IDはビルド時にエラーにします。実際の画像IDは既存カタログから選択し、瞬き・口・中間動作は既存の仕組みで再生します。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build-integration.ps1 -App glass
powershell -NoProfile -ExecutionPolicy Bypass -File tools/test-fullbody-scenes.ps1 -Serial [device serial omitted]
```

検証はインストールを行いません。APKとテストを `/data/local/tmp` へ転送し、AndroidのCanvasを含むテストを実行します。結果は `.build-integration/scene-verification/device-tests-verified.txt`。端末シリアルは実際の接続先に合わせて指定してください。

今回追加した5種類は、婉曲な拒否・耳への息への驚き・外見を褒められた照れ・喪失への共感・ユーザーの眠気への気遣いです。返答の「ありがとうございます」「ご案内します」だけで場面を上書きしないようにしました。拒否の保持・謝罪での解除、立ち座り、画像到達性、拾う動作、口の描画を既存テストでも確認します。

## 画像を増やす時の注意

座位の驚き・照れ・共感など、適切な専用画像が不足している感情があります。判定の追加だけではこの不足は解消しません。カタログの `seated` と感情・強さ・実画像を確認し、同じ人物の縮尺で画像と中間フレームを追加してから検証してください。違う感情の画像にラベルだけ付け替えないでください。

これは追加・検証しやすい規則ベースの仕組みです。自動学習やGeminiの構造化した感情出力は未実装です。未登録の言い回しはログから検証例へ追加して改善します。既存の全文応答→発話区切りの場面保持を利用するため、複数段階の反応を時系列で指定する専用データはまだありません。

v433はグラスへの更新、インストール済みAPKのハッシュ一致、起動、全身モード設定の保持を確認済みです。更新前のAPKとアプリデータはバックアップ済みです。装着しての見え方・会話との同期は別途確認が必要です。
