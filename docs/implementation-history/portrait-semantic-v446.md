# 顔モードへの意味判定反映 v446

全身モードの意味メタデータ生成を顔モードにも適用。本文からの内部タグ除去は共通。意味・強さを既存の顔表情IDへ対応付け、全身画像IDとは区別する。

- 拒否55、驚き44/45/46、喜び1、思案38、心配43、安堵52など既存の表情を使用。
- 返答全体の判定をRokid TTS・スマホTTS双方の開始処理へ渡す。発話の分割で普通の文へ切り替わっても、意味で決まった顔表情を維持する。
- 本文の拒否・怒り、既存場面判定を優先し、モデルの誤った喜び判定を補正。
- 意味判定の反応がある時、短い息遣いの文字列だけで別の発話顔へ上書きしない。通常の口のアニメーションと瞬き処理は維持。
- 発話を終えると表情固定を解除。次の返答・別世代のTTSには持ち越さない。
- 顔側の監査は `files/portrait-reaction-audit.jsonl`。本文を保存せずハッシュ・期待感情・表情ID・補正フラグを記録。約256KiBで一世代ローテーション。
- メタデータがない場合は本文・場面判定、それも不明なら既存の表情選択へ戻る。

## 検証

`tests/result.txt`: 顔表情レジストリ、驚き3段階、拒否の補正、引用・第三者除外、既存の全身意味判定テスト。

`device-test/result.txt`: 一時的に顔モードで実行。実際の顔Viewで拒否55を維持し、一般的な途中文と短い発話で上書きされないことを確認。発話終了で固定解除、口のアニメーション有効、瞬きの予定時刻を確認。顔モードの通常Gemini通信から `SURPRISE:1` を取得し、監査ファイルの保存も確認。

テスト後は元の全身表示設定を復元。検証用アプリを削除してロキを再起動。スマホは更新していない。更新前のAPK・アプリデータ・記録写真をバックアップし、更新後のAPKハッシュを照合。

上記は制御・状態の実機検証。装着して見た瞬きや口の自然さ、長時間の会話品質を評価したものではない。
