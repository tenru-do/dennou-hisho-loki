## 表示仕様案

選択肢は「顔」「全身」。既存利用者の初期値は顔とし、選択を永続化する。既存の会話・表情選択・音声状態は共通にし、表示モードだけを切り替える。

全身は利用可能な描画領域の左50%、情報は右50%を初期案とする。これはユーザーが最初に指定した左右配置を満たす案であり、実機で人物の占有高さと顔の可読性を測って決める。横長の画面に対して全身は細長いため、領域幅が半分でも人物がその幅を満たすとは限らない。

全身画像はアスペクト比を保ってcontainで表示。足元の基準位置を揃え、頭と靴を欠けさせない。座り姿も別の基準位置・高さを定義する。会話文は右側でスクロール、ステータスと操作ボタンは文字領域の中で再配置し、人物に重ねない。ナビ・地図・ダイアログなどの既存表示は専用レイアウトを優先し、閉じたら選択済みモードへ戻す。

グラスは緑色LED単色。原稿の白は緑の点灯、黒は消灯。肌の面を点灯させる採用方針を維持する。背景の黒は現実の背景を隠す黒い板を意味しない。顔や指の消灯線は背景・表示寸法によって読みにくくなる可能性があり、実機検証で調整する。

現段階は複数人物を並べた確認用シート。各画像の余白・寸法やポーズの位置には差があり、印刷されたID文字もあるため、そのまま再生用アトラスとして読み込まない。まず各人物の領域を明示的に記録して個別の描画用画像へ切り出す。これは画像を表示するための準備であり、アニメーション細分化とは別工程。

IDと画像パス、立ち/座り区分、描画領域、足元基準点をJSONなどの明示的な一覧で管理する。ID表示がないシートもあるため、原稿の読み順を確認して対応を固定する。欠損したIDでは全身の通常表情へフォールバックし、顔表示も選べるようにする。

## 実装の分担案

1. 表示設定：表示モードenumと専用設定キー。音声/会話の既存modeと混同しない。
2. レイアウト：画面の実測寸法から領域を計算する専用方針クラス。既存の顔用配置を保持。
3. 全身描画：専用FullBodyMascotViewなど。既存表情IDを受け取り縦長画像を表示する。顔用口・目overlayは適用しない。
4. 資産管理：現在/次の表情など必要な画像だけを読み込み、上限付きキャッシュを使う。画像読込みや大きな割り当てをonDraw内で行わない。

参考：384×768のARGB_8888画像は約1.125MiB。168枚を全展開すると約189MiB、各12コマなら約2.21GiB。これは仮の解像度に対する計算であり、採用解像度や端末の使用可能メモリの測定値ではない。

第4段階：ユーザーが後工程として指定したアニメーション細分化、位置合わせ、待機・歩行周期の修正へ進む。現状の6コマは完成した歩行サイクルではない。
