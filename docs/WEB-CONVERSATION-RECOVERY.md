# Webの会話状態・依頼文の復元（スマホ208）

会話欄に、グラスの最後の処理段階・通知の古さ・直近15秒以内の通信有無・スマホ側キューの件数を表示します。グラス全体の状態であり、個々のWeb依頼の成否を確定する情報ではありません。キューはTOPIC等の操作を含む全体の件数です。

状態の鮮度はスマホで受信した単調時刻を使います。グラス側の時計には依存せず、端末プロセスの再起動後に以前のREADYを新しい通知とは扱いません。最後の状態が2分以上前なら「最後の状態」として表示し、通信が15秒見えない場合も切断を断定せず「未確認」と表示します。

既存の認証済みhistory応答に、処理段階と件数だけのruntimeを追加しました。コマンド本文、APIキー、位置、画像等は追加しません。状態の読み取りによってキューを消費・再送しません。状態だけ変わった場合は会話DOMを作り直さず、閲覧位置を保ちます。接続解除で状態を消し、遅れて届いた前のセッションの履歴で埋め戻しません。

送信状況の各依頼に「入力欄へ戻す（自動送信なし）」を追加しました。別の下書きや添付・生成の編集元があれば、上書きや解除を確認します。元の添付は復元しません。戻した文章は新しい下書きとなり、実際の送信は別操作です。前の依頼がキューに残っている可能性を明示します。本文と時刻だけでは依頼IDの一致を証明できないため、共有履歴の同文を今回の送達確定とは表示しません。

スマホで保留案件を取消・削除した後は、受信箱件数を即時に再取得します。

検証：ローカル回帰143件（うち状態スナップショット12件）、合成データによるWeb操作12項目、スマホ実機4項目（状態の非破壊読み取り・公開フィールド・鮮度・受信箱再読込）。Geminiへの追加診断送信・画像や音声送信・予定登録は行っていません。新しい権限や公開APIは追加していません。
