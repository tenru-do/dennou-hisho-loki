# NAVIの移動手段別検証（2026-10-23）

## 結論

実APKのクラスで移動を再現し、2種類の不具合を検出・修正しました。修正後はモード別67ケースと既存1,713項目、合計1,780項目が成功しました。実サービスでは徒歩・自転車・車をGoogle、公共交通を設定済みNAVITIMEで取得できました。実際の移動は未検証なので、「すべての環境で問題なく案内できる」とはまだ判断していません。

|---|---|---|
| 徒歩 | 最初の曲がり、通過後、GPS逆戻り、精度低下、再開始、経路線、経路外判定、到着、曲がり通知文字列 | 15ケース成功。音声の実再生は未実施 |

## 発見して直した問題

1. **車の経路線が消える**：メガネの表示処理で、車が経路全体を使うモード一覧から抜けていました。GPSで区間を選べない状態でも、取得済みの車の全経路線を表示するよう修正しました。
2. **精度の悪いGPSで曲がり案内が抜ける**：進捗を保持していても、距離計算側では先へ飛んだGPSの経路点を使っていました。距離計算も保持済みの進捗に揃えました。徒歩・自転車・車の3ケースで再現し、修正後に解消を確認しました。

修正前は追加55ケース中4ケースが失敗（2原因）、修正後は追加した鉄道・バスの12ケースも含め67ケースすべて成功しました。

## 検証方法と限界

別UIDのテスト環境で、実APKのスマホ側案内計算メソッドとメガネ側表示変換を呼び出しました。位置・経路・駅・路線は合成情報です。端末のGPSを書き換えず、実際の案内を開始せず、録音・音声再生・実API検索も行っていません。位置計算と通知文字列の検証であり、実際の視認性、スピーカーからの音、道路の安全性を保証するものではありません。

## 実APIでの確認結果

許可を受けて東京駅〜上野駅の公開座標間で検索しました。個人の現在地・自宅・勤務先は使っていません。検索地点は駅の座標であり、個別の入口・出口まで確認したものではありません。

| モード・検索先 | 実際の結果 |
|---|---|
| 徒歩・Google | 成功。4,126m、案内13ステップ、経路線あり |
| 自転車・Google | 成功。4,304m、案内12ステップ、経路線あり |
| 車・Google | 成功。5,761m、案内13ステップ、経路線あり |
| 公共交通・Google | この検索では経路なし（google_route_not_found）。この結果だけで地域全体の非対応とは断定しない |
| 公共交通・設定済みNAVITIME | 成功。候補1件、アプリの経路形式への変換成功、11ステップ中公共交通1区間、経路線あり。接続区間のGoogle経路取得も成功 |

アプリの通常処理はNAVITIME設定済みの場合、公共交通にNAVITIMEを使います。この端末では設定済みであることを確認しました。Googleで経路なしでも、通常の公共交通検索先での取得は成功しています。

通信回数はGoogleの4回に、NAVITIME本体1回と接続区間2回を加え、合計7回。許可された最大8回以内で終了しました。追加検索は行いません。一時的な検証APKは削除済みです。NAVITIMEの暗号化された資格情報は不変で、元146ファイルのうち変化したのは期待されるNAVITIME利用回数情報の1ファイルだけでした。カウンターは巻き戻していません。

これは検索結果・経路線・アプリ内変換の確認です。実際の徒歩・走行・乗車、到着時の実動作、音声の聞こえ方、最新の運休や遅延への追従までは確認していません。
