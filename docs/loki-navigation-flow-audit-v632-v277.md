# NAVIの導線・異常系の横断確認（メガネv632・スマホv277）

## 結論

他の導線にも、空候補やキャンセル後に状態が残る処理、登録地点の読み込み中に前の目的地が残る処理、登録地点を選んだだけで開始ボタンまで実行する処理がありました。これらを修正しました。

従来の回帰検証の項目数だけでは、実ダイアログの選択中に通常の更新が割り込むといった操作全体を確認できていませんでした。今回、候補APKの実Activityメソッド・実Androidダイアログ・決定キーの処理を使う別の操作検証を追加しました。通信だけを合成応答へ置き換え、実際の地点・APIキー・現在地を使わずに実施しています。

## 結果

- 実ダイアログの操作検証：86ケース成功、失敗0。
- 従来の回帰検証：4,018アサーション成功（移動手段別67ケースを含む）。操作検証の86ケースとは別のものです。
- 両方の検証で使用したスマホ・メガネAPKのSHA-256が一致。
- 外部APIへの検索0回。勤務先への検索・実案内開始0回。検証アプリには通信・位置・録音の権限を付与せず、終了後に削除しました。

## 確認した導線

| 導線 | 実ダイアログ・処理で確認したこと |
|---|---|
| 公共交通の共通候補 | 取得→選択→確認→開始、確認キャンセル、候補の閉じる・戻る、空候補、通信失敗 |
| 登録ルート一覧 | ルート→区間→検索確認→候補→開始確認→開始／取消 |
| 行き・帰り | 指定したルートに絞って同じ選択・確認・開始／取消が進む |
| 次の区間 | 区間完了確認→候補→開始確認、次の区間がない場合の終了表示 |
| 乗り遅れ再検索 | 再検索確認→候補→開始確認、取消時に開始しないこと |
| 目的地・立ち寄り・別経路の変更 | 場所→経路→開始確認、途中の空候補、確認中に経路が変わった場合の拒否 |
| 登録地点から徒歩・自転車・車 | 移動手段を保ち、明示確認後に1回だけ開始。取消では開始しない |
| 自宅→勤務先の読み込み切り替え | 読み込み中は前の目的地を無効にし、古い地点で開始しない |
| お気に入り地点 | 地点の選択だけでは案内を開始しない |
| 通知・表示設定 | 徒歩・自転車・移動手段別表示の設定を正しい種類へ1回反映、取消時は送らない |
| 保存した出口・駐輪場所 | 一覧・詳細の閲覧と終了。空の場合に取得中を残さない |
| 乗車・降車・休憩・再開・到着・未到着・遅れ記録 | 指定した操作を1回送る。応答不明で再送しない |
| スマホの候補待機 | 時間切れで待機画面を閉じ、古いタイムアウトで新しい待機を閉じない |

スマホ側の操作検証は、実ダイアログを用いた待機終了・古いタイムアウトの処理を対象にしています。上表のすべてをスマホからも実サービスへ検索・開始したという意味ではありません。

## 割り込み・異常系

- 実際の定期ナビ受信メソッドに通信失敗・復帰の合成応答を割り込ませ、候補選択と開始確認のダイアログが維持されることを確認。
- 通常の案内表示リセットを繰り返しても選択・確認を閉じないことを確認。
- 取得中の取消、時間切れ、古い結果の後着、新しい検索への切り替え、古い段階のタイムアウト、同じ開始ボタンの連続決定、応答喪失、送信中の音声取消を確認。
- JSON不正、候補なし、途中の経路候補なし、入れ子の不正な区間情報、選択中の経路変更を確認。
- スマホの待機には75秒の上限を設け、待機終了・取消でダイアログ参照と検索状態を解除。空候補を空の選択画面にしません。

拡張検証の途中に出た2件の停止は、検証コードがUIスレッド内で同じスレッドへ処理を依頼して待っていたことが原因でした。検証側を修正後、上記86ケースの最終実行ではすべて成功しています。これら2件をアプリの不具合として数えていません。

## 再検証の方法

リポジトリに tools/navigation-flow-ui/ と tools/Verify-NavigationInteractions.py を追加しました。候補APKをビルドした後、単一コマンドで実ダイアログ検証と回帰検証を実行し、両方の結果と最終APKのハッシュが一致するか確認できます。検証用の応答差し替えはプロセス内の依存関係だけで、利用者が設定・Intent・HTTPから有効にする入口はありません。

## 残る範囲

実際の勤務先ルートの取得、実サービスの応答時間、実走・乗車中のGPS・到着・読み上げ・運休遅延は、この操作検証では確認していません。「どの環境でもすべて正常」とは断定しません。

## 端末への適用

スマホv277・メガネv632ともに適用済み。署名・バックアップ・適用APKハッシュを照合し、スマホの既存147ファイル、メガネの既存411ファイルの内容を起動前に保持確認しました。
