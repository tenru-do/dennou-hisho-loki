# 画像参照の送信時照合・通知の通常経路試験（スマホv222）

## 実装

「添付Nについて質問・訂正」で選んだ参照に、時刻・件数・質問・読み取り結果・添付種類から求める識別キーを付けます。キーに画像本体・位置を追加しません。

スマホは書き出しとキーを下書きに保持し、送信ボタンを押した時に最新の有効な参照と照合します。画面の保存状態にも書き出しとキーを引き継ぎます。PC・タブレットではWebの下書きに同様の対応を入れ、さらにWeb受付側でも照合します。変化・失効があれば送信待ちへ入れず、本文を残して選び直しを案内します。受付済みの同じWeb依頼IDは、再投入せず従来どおり重複として返します。

別の添付や生成編集元との混用を防ぎます。質問の書き出し自体を消して別の文章にした場合は、参照指定を解除します。通常の会話・新しい画像添付は従来の経路です。参照キーはGeminiへ渡しません。会話プロンプトやモデルの送信形式を変更していません。

## 検証

- ビルドと会話プロンプト基準2区間の検査成功。
- ホスト回帰404項目成功。識別キーの一致、同時刻でも内容が異なる場合、失効、不正キー、再シリアライズなど7項目を追加。
- ブラウザ56項目成功。参照失効時の未送信、本文保持、参照キー付きの送信を確認。最初の試験で閉じたパネルと残った合成添付が後の操作を妨げたため、試験コードの状態初期化を直して再実行しました。
- スマホv222実機49項目成功。暗号化保存からキーを取得し、参照更新で旧キーが無効になること、新しいキーが一致することを確認。合成データ・隔離保存先で実施し、カレンダー登録・AI送信はありません。
- スマホ更新前の機種・署名を照合。旧APKとアプリデータのバックアップを読み取り検証し、端末／PCのSHA-256、インストール済みAPKのSHA-256一致を確認。グラスはv575を維持。

## 通知の通常経路

グラスの実際のMainActivityの通知処理へ合成通知を投入しました。初回は優先処理によって保留され、表示・音声処理は開始しませんでした。画面復帰後の試験では1件を受理し、実画面に表示しました。

同じ試験時刻帯に「Rokid native TTS sent」の定型ログが1件あり、Rokid音声サービスへの送信まで確認しました。最初に使ったttsGenerationは再生回数ではなく取消世代のため、変化しないことを音声未送信の根拠にはしません。本文や生ログは保存せず、定型マーカーの件数だけを記録しました。物理スピーカーで聞こえたか、装着者による聞こえ方は未検証です。追加のGemini送信はありません。通知テスト用IDが残っていた場合だけ、直前の重複抑止IDへ復元しました。

## 範囲と残る課題

今回の照合は選択時・送信時・Web受付時です。受付後のキュー待ちからグラスが実行するまで、元の画像を保持して実行対象へ固定する新しいプロトコルは追加していません。そこで参照が変わる場合まで解決したとは扱いません。識別キーがない古いクライアントや、参照一覧を使わず入力した自由文に、この明示的な下書き照合は適用しません。

新しいAPI送信先・Android権限・写真や録音の取得はありません。既存未コミット変更を保持し、GitHubへpushしていません。更新前バックアップはローカル保管で公開対象外です。
