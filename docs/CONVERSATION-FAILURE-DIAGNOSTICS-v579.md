# 会話失敗の診断分離（グラスv579）

通信・API・処理の失敗文を、Geminiの完了回答としてスマホの会話ログへ送る処理を削除した。これから発生する失敗の理由は、端末内のlast_conversation_failureへ固定理由コード・処理段階・時刻だけを保存する。過去ログや保存済みの会話は変更・削除しない。グラスの「依頼・転送・動作チェック」から直近の停止理由と段階を確認できる。

タイムアウト、接続不能、中断、利用制限、認証・権限、請求設定、モデル利用不可、一時的なAPI障害、API受付失敗、回答候補なし、出力上限、画像参照の変更、安全判定、その他の処理失敗を固定語彙で区別する。分類では包まれた原因も最大8段だけ確認する。未知の原因・段階は一般的な処理失敗として表示し、例外の本文を画面・診断へ転記しない。通常会話の最終エラーログにも固定の段階と理由だけを出す。

失敗時の送信ボタンの再有効化、既存の待機時間、ID付き依頼のFAILED通知、安全判定時の履歴除外は維持する。ID付き通知の理由コードは既存互換のMODEL_ERROR等を使用し、新しい固定理由は端末内診断に保持する。再送動作やモデル選択は今回変更していない。既存のAPI処理中の再試行と、失敗画面からの再送は区別する。

## 検証

- ホスト回帰593項目成功（新規の分類・秘密文非表示・循環例外75項目を含む）。
- 会話プロンプトの18保護区間は変更なし。通常ビルド・173ソースのコンパイル・APK検査成功。
- インストール済み実クラスを使った実機255項目成功。既存125項目、新規ポリシー75項目、実際の失敗記録処理55項目。合成例外・隔離設定を使用し、実履歴は書き換えていない。
- 実機記録処理では包まれたタイムアウトや接続例外、HTTP例外、出力上限による候補なし、参照失効、安全判定を与え、固定コードと段階・時刻だけが残ること、合成履歴が変わらないこと、安全判定の記録が適切に分離されることを確認。
- コンパイル済みMainActivityのrecordFailedConversation両オーバーロードに会話ログ送信・Thread生成・非同期ディスパッチがないことを検査。コード検査と実機記録試験を組み合わせて検証したもので、外部API障害を実際に発生させた試験ではない。
- 今回、Gemini API・画像・音声・検索・予定登録への送信は0件。モデルの回答品質や新たなプロンプトの実API検証は行っていない。

## 端末反映

グラスv579へ反映。スマホv224は変更なし。対象機種・署名一致、更新前APKのPC／端末ハッシュ一致、更新前データのPCバックアップ・ハッシュ・全アーカイブメンバー読み取り、インストール後APKのハッシュ一致を確認。

両端末の起動時ローカル検査に合格。実際の状態同期を呼び出し、スマホの暗号化状態ファイルが確認時点の26秒前に更新されていたことを確認。会話本文や位置情報は読み出していない。検証アプリと一時DEX・結果キャッシュは削除し、ロキ本体を起動する。

## 限界と継続課題

今回は例外として停止した失敗の表示・記録を対象にした。通常応答に本文が含まれたまま出力上限に達するケースの完了判定は別途の修正対象であり、この変更で未完了回答をすべて防げるとはしない。正常応答の保存・読み上げの経路は今回変更していない。長時間複合稼働、装着中の見え方・読み上げの確認も未実施。既存のAPI待機・再試行方針はそのまま。

既存未コミット変更を保持。GitHubへpushしていない。バックアップ・端末識別情報を含む詳細結果はローカルに保存し公開しない。
