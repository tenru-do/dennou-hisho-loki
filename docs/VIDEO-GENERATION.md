# 通常会話からの動画生成

2026-10-16: グラスv537／スマホv195。既存の未コミット変更を保持。GitHubへの公開は今回実施していない。

## 使い方

- 通常の会話入力で「ロキが笑顔で手を振る動画を作って」「この画像を動画にして」。生成中も会話を続けられる。
- スマホの会話横に「動画生成・生成動画一覧」。生成画像の詳細には「この画像を動画に」。PC／タブレットのWeb会話にも生成動画一覧を追加。
- ロキ自身の依頼は採用済みの全身ID4・顔ID0を参照する。添付画像や明示選択した生成画像がある場合は、その画像を開始画像として優先する。無関係な過去画像は自動添付しない。
- 再生はスマホとWeb。グラスは依頼と完了状態の案内を担当する。生成動画を既存アバターアニメーションに自動採用する機能ではない。
- 生成したMP4はスマホの Movies/Loki/Generated/ へ保存する。Webからも原本をダウンロードできる。ロキ内からの削除ではギャラリーのコピーを消さない。ロキ内記録の削除は、API側の生成依頼の取消ではない。

## 実装

`VideoGenerationPolicy` は明示的な動画制作依頼を判定し、機能への質問・否定・解析依頼・内部コマンドを除外。普通の会話、添付画像、認証済みWeb、認証済みグラスブリッジの入口を接続。

`VideoGeneration` は Veo 3.1 Fast (veo-3.1-fast-generate-preview) へ1件ずつ8秒・720pを依頼する。本人画像があれば通常は縦9:16、明示指定で横16:9。動画API利用料が発生する。Google公式料金表の確認時点でFast720pは1秒0.10米ドル、8秒で0.80米ドル。将来変更される可能性がある。

公式SDKの形式に合わせ、画像はmimeType／bytesBase64Encoded、参照種別はASSETとして送る。画像生成APIのinlineDataとは異なる。最初の実API試験はHTTP400で拒否されたため修正した。エラー詳細は暗号化して記録し、診断のためだけの有料API再送を不要にした。

受付IDと進捗は暗号化して保存する。再起動時は、受付IDがある処理をGETで追跡し、POSTで作り直さない。POST送信中に終了して受付が不明な場合も自動再送しない。長い待機や取得失敗は結果確認を休止し、利用者の操作で同じ受付IDの結果確認を再開する。安全基準で拒否された結果を自動再生成しない。

動画は256KiBずつAES-GCM暗号化する。全MP4をAndroidのUIヒープに保持しない。1本32MB、ロキ内20件／合計約256MBを上限とする。ギャラリー公開前にSHA256と実動画の長さ・寸法を確認する。保存途中のMediaStore行を再利用し、利用者が削除した公開済みコピーを自動復元しない。

Google動画の取得先をHTTPSの指定Googleホストへ限定し、APIキーはgenerativelanguage.googleapis.com以外へのリダイレクトに転送しない。APIキー・受付ID・内部診断はWeb一覧に返さない。Webセッションとブリッジ認証は分離する。指示と指定元画像／同梱本人参照以外の写真・位置・連絡先・会話履歴を、動画生成のために自動送信しない。

- 更新前に対象モデル・署名・バックアップのPCコピーとハッシュ、更新後APKと設定保持を確認。
- 通常Web会話から実際に1本を生成。登録画像2枚を参照し、8秒／720×1280／814,866バイトのMP4が完成。ギャラリーmedia/4183。SHA256: 990a79430e9dda6974dd88abe50867881bb24a4f204618cbf02357c515fce89e。

- 暗号化保存・ギャラリーとのバイト一致・改ざん拒否・保存途中行の再利用・重複保存防止・削除済みギャラリーコピーを自動復元しないことを確認。テスト用コピーは削除し実動画は保持。
- スマホで動画を閉じて会話へ戻り、IMEアニメーション完了後に2行入力と送信欄がキーボードに隠れないことを確認。
