# 未完了依頼の見落とし・再起動後の通信状態表示（スマホv218）

## 変更

共通確認画面の会話12件は、未完了・結果未確認を先に並べ、その中で新しい順に表示します。後から完了履歴が増えても古い未完了案件が押し出されにくくなります。13件以上の未完了がある場合は、この画面だけで全件を表示するものではありません。元の送信履歴は保持します。

長く送信待ちの場合は通信復帰だけでは実行結果を判断できないことを表示し、結果未確認は自動再送しないと明示します。録音などの継続処理は、時間が経っただけで失敗に変更しません。表示の並び替えで依頼記録を更新しません。

スマホのプロセス再起動後は、ディスクの状態だけでグラスと最近通信できたと判断しません。現在のプロセスで受信し、単調時刻で15秒以内の状態だけを新しい通信と表示します。起動時に保存済みの予定・写真・会話を再実行しません。

## 継続観測ツール

`tools/observe-loki-process-health.py` に、最大120分の読み取り専用観測を追加しました。ADBパス、グラス・スマホの各serial、時間、間隔、保存先を明示して実行します。保存するのは経過秒、プロセスID、PSSメモリ、取得可否と集計です。端末serialはソースや結果へ保存しません。全logcat・音声・写真・位置・会話は収集しません。アプリや撮影・録音・AI通信を開始・停止しません。

PSSが取れない場合を0MBと扱わず、端末取得不能とプロセス不在を分けます。PID変化は観測できた変化だけで、サンプリング間の再起動をすべて保証するものではありません。PSS増加だけでメモリリークとは判定しません。中断しても直近の保存済み観測結果が残ります。

パーサ・集計の合成検査4項目成功。今回の実測は2分の通常起動状態の観測で、TOPIC・KEEP・録音を組み合わせた長時間負荷試験とは別です。
