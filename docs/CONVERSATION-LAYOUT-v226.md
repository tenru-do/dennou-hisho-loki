# 入力欄・会話ログ配置とニュース理解（グラス582／スマホ226）

## スマホの配置

画面全体を囲むScrollViewを除き、コメント入力を最上部、会話ログをその下の残り高さを使う独立したスクロール欄にした。入力・送信操作をスクロールで隠さない。固定のログ高さや添付時の高さの差し引きを除去。添付・生成物・画像参照・ナビ・TOPIC・設定は下部の開閉欄へまとめ、キーボード表示中は補助欄を隠す。テザリングは下部の常時押せる操作として維持。

Android30以降はedge-to-edgeのinsetsを外枠で受け、システムバーとIMEの大きい方を下余白に使う。旧版AndroidはadjustResizeと安定したシステムバー余白を使い、IMEを二重に引かない。入力・添付の送信処理と下書きは既存経路を維持し、選択・表示のみで送信しない。

スマホ226はビルド・対象機種・署名一致・更新前バックアップ・反映後APKハッシュを確認して反映。実キーボードを表示した12項目の実機確認が成功し、入力欄とログがキーボード上に収まること、入力欄の下に578pxのログが見えること、下書き不変を確認。送信操作とAPI呼び出しは0件。通常画面も目視確認した。

## ニュースの理解

通常会話を単語削除式の直接ニュース処理へ分岐させる呼び出しを外した。発言全文と既存の会話文脈を、Google検索ツールを持つ通常のGemini会話処理へ渡す。フィラーの言葉を検索名詞として機械的に扱う近道を使わない。通常会話プロンプト本文自体は変更していない。

接続グラスへ582を、機種・署名・更新前バックアップ・SHA256・反映後APKのSHA256を検証して反映。専用の隔離設定から、実履歴・カスタム設定・画像・音声を含まない合成発言2件を本番のrequestGeminiへ送信。報告例は一般ニュース、別の言い回しは宇宙開発ニュースとして、両方が出典付きで応答。実履歴は不変。自動再送・カレンダーや記憶の変更なし。試験IDの回数記録で2件に制限した。

これは2例の依頼解釈の検証であり、モデルの全発言理解や各ニュース項目の独立した事実検証を保証しない。モデルの誤答や検索エラーは依然として起こり得る。

## 容量の調査

グラスに過去の更新前バックアップZIPが57個、合計13,056,535,408バイト（約12.16GiB）残っていた。今回確認した主要な容量圧迫の原因。これらは今回削除していない。アプリの写真領域は約4MiB。前段階でPCコピーとハッシュ一致を確認して整理した26個のcache内tarとは別の古いZIP群。

現在の更新手順は新しい一時バックアップをPCへ保存・照合し、反映後にその端末内一時コピーを消す。既存57個の整理には各PCコピーの所在・ハッシュを照合し、必要なバックアップを確保してから行う。写真・録音・設定の一括消去は行わない。
