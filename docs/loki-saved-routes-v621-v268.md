# よく使うルートとナビ案内の改善：メガネv621・スマホv268

## 個人情報の扱い

ご提示の住所・停留所などの個人情報は、ソースコード、APK、初期設定、説明資料へ収録していません。端末への初期登録や、その情報を用いた検索も行っていません。

ルートは利用者が端末で入力し、明示的に保存した場合のみ端末内で暗号化して保存します。地点候補や経路の検索を実行した際は、検索に必要な地点情報が既存の検索サービスへ送られます。暗号化保存は、検索時にも情報を外部へ送らないという意味ではありません。

## 使い方

1. スマホのNAVIにある「よく使うルート・区間指定」を開く。
2. 新規作成、または移動手段だけを組んだ匿名の下書きを選ぶ。自動登録はない。
3. 行き・帰りを別の名前で作り、各区間の出発地点・到着地点を候補から選ぶ。前区間の到着地点を再利用できる。
4. 徒歩・自転車・電車・バスを指定する。電車・バスは乗降駅／停留所が必須。路線名、入口・出口のメモは任意。
5. 「端末内に暗号化して保存」を押す。未入力の区間は下書きとして残せる。
6. 利用する区間を選び、現在時刻の候補を検索する。現在地が区間の出発地点から離れている場合や、位置が古い場合は開始しない。
7. 候補と移動手段を確認して開始する。次の区間は、降車・駐輪などを終えてから「次の登録区間を確認」で進める。GPSだけで乗降や区間完了を判定しない。

メガネのNAVメニューからも、保存済みルートの選択・候補確認・次区間の確認ができます。編集・保存はスマホで行います。

区間は最大12件、ルートは最大20件。列車やバスの古い検索結果は保存せず、利用する区間を検索し直します。指定条件に合わない候補は採用せず、候補がないことを表示します。自転車区間を徒歩へ自動変更しません。候補は3分で期限切れとなり、編集・削除・現在のナビ状態の変更・出発地点からの移動があれば開始前に再確認します。

## 合わせて改善した案内

- 出発方向を確認中と、移動方向を確認できた状態を区別し、未確認の左右案内を抑える。
- 到着地点の近くでは、利用者が指定した入口・出口メモを表示する。未指定なら未確認と表示し、入口を推測しない。
- 検索サービスの経路に横断歩道・階段・地下道などの指示がある場合に案内する。信号や通行可能性のリアルタイム確認は行わない。
- 再検索中の状態通知を重複させず、古い方向案内を止め、経路が確定した後に案内を再開する。
- 公共交通の各段階で「次にすること」を上部に大きく表示する。取得できた乗降情報を使い、ホーム番号などを作り出さない。

## 検証範囲

両アプリのビルドと、実際の候補APKクラスを用いた別UIDの隔離検証を実施。合成地点・合成レコードのみ使用し、暗号化保存、更新競合、破損記録の保持、交通手段と乗降地点の一致、候補の期限、重複開始、案内の重複抑制を確認しています。

検証ではAI送信、実経路検索、録音、音声再生を行っていません。実際の通勤経路、移動中のGPS・方角、音声タイミング、画面の見え方は別途実機での確認が必要です。対応地域や契約中の検索APIによって、希望する自転車・公共交通の候補が取得できない場合があります。
