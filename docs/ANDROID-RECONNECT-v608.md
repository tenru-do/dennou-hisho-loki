# ロキ：回答の取り込み・接続復帰・質問ごとの状態

対象：メガネv608、スマホv256。スマホv255の通信不要の一覧も含みます。

## 1. メガネだけにある回答をスマホへ取り込む

メガネで得た会話の本文を暗号化して転送待ちに保存します。接続中にスマホへ順次取り込み、スマホから該当IDの保存確認が返るまでメガネの転送待ちに残します。回答ログだけを同期し、AIへの質問や予定登録は再実行しません。

スマホの会話画面に「未取り込み回答」の件数を表示します。切断中の値は最終受信時点と明示し、状態を読めない場合は0件と表示せず「未確認」とします。転送待ち件数は、厳密にはスマホの保存確認がまだ返っていない回答の件数です。

保存済み本文は通信状態表示をタップ、または「記録」→「保存済みメモ・回答（通信不要）」から閲覧できます。検索語なしで一覧を開け、メモ・未送信メモと会話・読み取り回答を絞り込めます。

更新前の履歴は、メガネに実際に残っている会話コンテキストだけを取り込みます。以前から短く保存されていた本文は「更新前の保存履歴・抜粋」と表示します。すでに失われた回答・切り詰められた続きは復元しません。既存のスマホ履歴に同じ本文がある過去の抜粋は表示を重複させません。

## 2. 接続復帰を知らせ、送信待ちは内容確認後に再開

メガネからの連絡が15秒以上途絶えた後に戻ると、スマホ・Webに復帰を表示します。復帰通知の表示時間は2分です。接続の判定はメガネからの通信の観測であり、AIサービスの到達性を保証しません。

復帰時に残っていた追跡付きの会話テキストは確認待ちになります。「送信状況」から対象の質問を開き、「内容確認・送信を許可」を選ぶと、そのIDの質問だけ送信待ちを再開します。新しいIDで複製した依頼は作りません。Webの送信状況からも同じ操作ができます。編集・取消も従来どおり可能です。

メガネ受理済みの質問は、新規の依頼として自動再送しません。画像添付・生成・保守コマンドは、このテキスト質問用の復帰確認の対象外です。

## 3. 質問ごとの接続トラブルを表示

- 受付・送信待ち：メガネの受理未確認。未到達とは断定しません。
- メガネ受理済み・処理中：新しい依頼としての重複送信を控えるよう表示。
- AI通信失敗：記録された理由と、部分的な結果・操作の実行結果を確認して再送を判断する案内。
- 回答完了通知だけ受信：メガネで回答完了、スマホの本文受信は未確認と表示。
- 回答本文を確認：回答受信済み・スマホに保存済みと表示。

## 保存と検証

メガネの転送待ちとスマホの取り込み済み本文はAndroidKeyStoreによるAES-GCMとAtomicFileで保存します。同一IDで異なる内容の取り込みは拒否します。確認応答が失われて同じログを転送し直しても、重複取り込みしません。容量上限・読み取り異常では保存成功の応答を返しません。

共有履歴から削除した取り込み済み本文は、本文を除いた受領記録を残し、再転送で一覧へ復活させません。メガネの転送待ちは最大1000行、スマホ側は受領記録込み2000行、各保存領域は16MiBを上限とし、自動的に古い未転送回答を捨てません。今回の保存領域は、従来の手動バックアップ対象には追加していません。

実機では、同期件数0件・スマホの暗号化保存領域・保存済み本文の入口・送信状態画面を確認しました。待機中のメガネ版を短時間再起動し、接続未確認から復帰通知への変化と、送信待ちが空のまま維持されることを確認しました。端末のネットワーク設定は変更せず、新しいAI質問も送信していません。

質問の確認待ち・選択したIDだけの許可・重複取り込み・確認応答の消失・暗号化・削除後の再転送は、権限を持たない別UIDのAndroidテストアプリと合成データで検証しています。ブラウザも合成データで検証しました。APIキーを抽出する検証は行っていません。

実機には開発署名の候補APKを、既存データのバックアップと署名照合後に上書き更新しています。公開用署名APKの作成、GitHubへのpush・リリース公開は今回まだ行っていません。
