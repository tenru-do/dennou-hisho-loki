# NAVIの流れ・速度対応と負荷検証 — メガネv627・スマホv274

## 実装した内容

- 自転車の曲がり通知を速度に追従させました。通常設定の予告は速度×45秒を基準に150〜500m、直前通知は速度×5秒を基準に15〜50mです。取得できない速度では従来の距離へ戻します。通知済み段階の保持により、停止と再加速だけで同じ段階を繰り返しません。
- 徒歩で約25〜45m、自転車で約60〜120m以内に次の曲がりがある場合、現在の案内へ「その後すぐ、左折です」などをまとめます。駅・降車・乗換の案内は混ぜません。短い読み上げ設定でも近い次の曲がりを残します。経路・曲がりが変わると既存の待ち音声を無効化します。
- GPSの欠落・精度不足・15秒を超える更新間隔の後は、原則として新しい有効な位置情報を2回、少なくとも1秒の間隔で確認するまで曲がり音声を保留します。同じサンプルの再受信は2回に数えません。初回や新経路は履歴を取り直します。
- スマホの案内作成・文字列化、問い合わせ往復、メガネの受信処理・画面待ち・次のフレームコールバックを分けて計測します。「ナビの応答時間」から直近120件の中央値と95%点を確認できます。位置情報の経過時間もスマホ側で計算して送ります。端末間の時計差を遅延として扱わず、住所・経路・会話・キーは計測値に保存しません。各時間には重複があり、単純に足し合わせる値ではありません。
- 6時間分の合成トレースと実時間2分間の連続負荷テストを追加しました。検索の最新結果優先、待ち音声の失効、GPS断と復帰、音声入力・回答待ちの状態を再現しています。

## 検証結果

回帰テスト1,763項目と移動手段別67ケース、合計1,830項目が成功しました。別UID・通信/録音/再生権限のない環境で実APKのクラスを検証しました。

- 6時間分：21,600サンプルを時間を進めて再現。実際に6時間放置したものではありません。
- 実時間の負荷確認：120.2秒、2,358更新。
- 実APKの案内計算：合計2,396回呼び出し。
- 画面スレッドへの確認処理の最大待ち：1ms。実描画完了や通常利用全体の応答時間ではありません。
- GC後の使用メモリ：3,249,600→3,610,048bytes（増加352KiB）。この短時間テストで異常な増加は観測していませんが、実利用での長時間リーク不在の証明ではありません。
- 検索ワーカー2・待機1・計測履歴120件という上限を超えないことを検証しました。

実際のマイクとTTSの同時利用、実道路での移動、走行中の視認性、実音声の開始時刻は未検証です。今回の新たな外部API検索は0回です。

## 適用と端末間の実測

適用状況：スマホv274・メガネv627とも適用済み。バックアップ・署名・インストール済みハッシュと、起動前の既存データ保持を照合しています。

位置・経路を使わないローカル通信専用の検査を5回実施。問い合わせ往復の中央値は332.4ms、最大602.8msでした。受信から次のフレームコールバックまでの中央値は10.4msでした。これは通信専用パケットの値で、実NAVIの案内作成・最終描画・音声待ちの実測ではありません。
