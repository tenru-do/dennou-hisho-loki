# v450 AMB実入力確認と応答形式修正

v448の実機確認で、環境音から76文字・2文のコメントと思案の画像・TTS動作を確認した。一方、GeminiがJSONではなく通常の文章を返した回にJSONObjectの解析が失敗し、その反応が捨てられていた。実入力で見つかった問題のため、合成データの表示テストだけでは完了としなかった。

v449で [Gemini公式の構造化出力](https://ai.google.dev/api/generate-content) に従い responseMimeType=application/json と responseSchema を指定した。コメント・感情・強さの項目と型を固定した。その後、静かな入力に対して「情報がないのでコメントできない」と述べる問題も実機で見つかった。

v450では hasEvent 判定を構造化出力に加え、新しい意味のある出来事だけに反応する。無音・判断不能・変化なし・前回と同じ出来事・グラス自身の通知や撮影音だけでは反応を作らないよう、AMB専用のシステム指示を追加した。hasEvent=falseと、実際に発生した空入力報告の文面を表示・発声前に除外する。例外ログは種別だけとし、生成コメントを例外経由でLogcatに出さない。開始時の「無音で解説表示」という旧案内も、場面にコメント・表情・動作で反応する内容に訂正した。顔・全身の意味反応、TLS、写真暗号化、撮影上限は維持する。

## 実機で確認した範囲

同じ署名でバックアップ後にグラスv450へ更新し、搭載APKのSHA256を照合した。環境音モードで実際にGeminiを呼び、87文字・2文のコメントの表示・TTS送信・座位待機への復帰を確認した。4回の取得完了を観測した期間でJSON解析エラーは0、発声コメントは1回、空入力報告の表示なしだった。受信成功や待機状態に由来する笑顔切替もなかった。コメント長さは目安であり、入力が短い場合は90文字未満でも許容する。

空入力報告の除外を実際の文面で回帰試験し、感情・強さ・発話分割・静かな待機の既存試験も通過した。グラス84ソースはerrors=0 / warnings=0。端末上のバックアップ一時ファイルと一時検証ツールは削除済み。検証前のAMB設定は停止・音＋カメラだったため、検証後はその2項目を戻した。連携トークン・共有記憶等の別項目は変更していない。

実際のお笑いライブ、人物会話、様々な喜怒哀楽を網羅したものではない。装着時の見え方、実際の音声が聞こえること、映像の理解の正確さは別の確認が必要。今回の87文字のコメントが周囲の実際の出来事と完全に一致していたことまでは検証していない。ローカルの画面XML・バックアップに個人的な情報が含まれ得るため、これらをGitHubへ登録しない。
