# 画像参照の更新・失効保護（スマホv220）

スマホv220を反映。グラスはv574を維持しています。既存の未コミット変更を保持し、GitHubへpushしていません。

## 変更

スマホの「参照を見る」は、開いた時点の読み取り結果を固定して表示します。裏で別の画像の読み取りが届いても、開いている画面の「全文」だけが新しい結果へ入れ替わらないようにしました。

「添付Nについて質問・訂正」を押す時点で、表示中の参照と最新の有効な参照の時刻・件数・質問・回答・添付種類を比較します。更新・失効していたら入力欄を書き換えず、閉じて最新の一覧を開き直すよう表示します。

「直近の画像を使う」の端末操作は、スマホ受付時点でも画像の識別時刻と有効期限を確認します。古い画面の画像指定や期限切れ指定をキューへ追加せず拒否します。これはスマホとWebに共通の受付検査です。グラス側の最終照合も維持します。

## 検証

- 通常ビルド成功。会話プロンプトの基準検査2区間成功。
- ホスト回帰381項目成功。うち7項目は参照一致、新しい参照、期限切れ、同時刻でも内容変更、件数変更、欠落と原データ保持の追加検査。
- スマホv220実機44項目成功。古い画像・期限切れの拒否、拒否時のキュー非変更、最新画像の受付を追加。合成データと隔離保存先を使用し、予定登録やAI送信はありません。
- 最初の追加試験は、前の試験で埋まった隔離キューにより停止しました。検証コードで試験用キューだけを初期化して再実行し、44項目を完了しました。アプリ本体のコード変更や実ユーザーのキュー削除は行っていません。
- 更新前の機種・署名・旧APKのハッシュを照合。バックアップ全メンバー読み取りとSHA-256を検証し、反映済みAPKのSHA-256一致も確認。

## 範囲

比較する参照情報は既存の暗号化保存の範囲内です。新しい外部送信・権限・撮影・録音・予定登録は追加していません。会話プロンプトやモデルの送信形式も変更していません。

質問の書き出しを入力欄へ戻した後、送信までの間に参照が変わるケースまで、今回のボタン選択時検査で完全に固定できるものではありません。送信時の参照ID固定やモデルの読み取り品質の検証とは区別します。

反映後の共通確認・会話参照・録音確認の3画面と、グラスからの新しい状態受信を確認しました。スマホv220の起動時ローカル検査も合格。検証用アプリは両端末から削除しています。
