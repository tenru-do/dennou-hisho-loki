# 秘書の受信箱・会話の引き継ぎカード（グラス554／スマホ204）

追記：グラス555／スマホ205では自然文の入口を文脈による意図判定へ変更。現在の仕様は [意味判定の説明](SECRETARY-INBOX-SEMANTIC.md) を参照してください。以下は554の保存・確認基盤の説明です。

## 使い方
- 会話のあと「このイベント、家族に聞いてから登録したい」「これを保留にして」「受信箱に保存」と送る。
- スマホへ保留依頼と、その時点の直近の会話を暗号化保存する。保留の保存だけで予定を登録しない。
- 後日「この前のイベント、登録して」「保留案件を見せて」。候補が複数なら対象を選ぶ。1件ならその案件の確認処理へ進む。
- 登録先や日程が不足すれば補足し、登録前確認に表示された内容を確認する。
- 「確定して登録」で、確認した候補だけをスマホのカレンダーへ保存する。保存済みの同じ確定要求には既存の結果を返し、重複登録しない。
- 確認期限は10分。案件本体は期限経過後も残り、再開できる。

## 開く場所
- グラス：SET → 秘書の受信箱、または会話で「秘書の受信箱を開いて」。
- スマホ：写真・記憶・共有の「秘書の受信箱（保留案件・引き継ぎ）」。
- PC・タブレット：ロキと会話の「秘書の受信箱・引き継ぎカード」。
- スマホ・Webで依頼、元の会話、日程・出典の記載を確認し、取消・削除できる。Webの再開ボタンは会話欄へ対象IDを入れる。送信・確定は別操作。
- 保留取消・案件削除は、すでにGoogleカレンダーへ登録した予定を削除する操作ではない。

## 保存する情報
スマホを正本に、最大100件。明示した依頼、表示用題名、参照用会話、会話内にあった出典URL、作成日時、状態、変更番号、短期の登録確認候補を保持する。自動削除・自動実行はしない。
参照会話は保存時点から2時間以内、最大6メッセージ・合計26000文字。長すぎる参照は打ち切り、無制限に履歴を集めない。イベント名・日程などは元の会話の記載として保持し、未取得の項目を埋めない。複数イベントを含む元回答では、登録対象を確認する必要がある。
外部ページの写しや最新情報の再取得ではなく、保存した時点の参照情報である。古い開催日などは登録前に確認する。

## 保護と失敗時
- Android Keystoreを利用するAES-GCMとAtomicFileで受信箱を保存。復号失敗時に空の受信箱で上書きしない。
- グラスは既存の認証付きTLS経路を使用。Webは既存セッション・同一オリジン検査の後に処理する。
- 保存ID、案件ID、変更番号、確認トークンを区別。確認候補はスマホ側に固定し、最終確定でモデルに再生成させない。
- 期限切れ・候補差し替え・取消・削除後の確認要求は拒否。
- カレンダー操作前に「実行中」を保存。操作途中で成否不明になったら「結果要確認」とし、自動再実行しない。カレンダーを手動確認する。
- 案件を取り出して登録候補を作る際は、元の会話情報を設定済みGeminiへ送信する。保留の保存時は新しいGemini送信を行わない。
- 会話ログ削除とは別の保存領域。不要な案件は受信箱から削除する。100件を超えると整理を求め、既存案件を勝手に捨てない。
- 登録時の端末内保存とGoogle側の同期完了は区別する。

## 検証範囲
PC上の保存処理27項目、意図判定26項目、ブラウザーのカード表示・選択ID・取消・HTML無害化を検証。保存テストは本番のSecretaryInbox／PhotoVaultCipherを使用し、AndroidのContext・AtomicFile・CalendarWriterはホスト用代替である。Android KeystoreやCalendarProviderの実機試験と同一ではない。
グラス・スマホの開発版ビルド、従来の会話指示の保護チェックを実施。実機への更新、実会話のモデルによる予定候補作成、実Googleカレンダーへの登録は今回未実施。

再実行：
`powershell -NoProfile -ExecutionPolicy Bypass -File tools/Test-SecretaryInbox.ps1 -JsonJar <org.jsonのローカルjar>`
テスト専用org.jsonは20240303を使用。アプリへ新しいJSON依存を追加していない。

## 現段階の範囲
受信箱には一般の保留メモも保存できるが、実行の確認フローはカレンダー登録を先に実装した。メール送信・購入・外部アプリの自動操作は実行しない。
複数案件を自然文の意味だけで一意に選ばず、選択画面を出す。公式GeminiやCodex全履歴との自動同期ではない。
