# HEALBE水分補給通知のスリープ復帰 v691 / v298

## 修正

ロキの旧通知リスナーはHEALBE通知を短縮保存するだけで、専用の水分アラート転送を行っていなかった。通常の__LOKI_ALERT__表示も、Codex専用の点灯待ちを利用していなかった。ユーザーが従来見ていた通知がRokid側の転送だったかは未確定なので、その経路まで修正したとは扱わない。

公式アプリ `com.healbe.healbegobe` の水分補給を促す日本語・英語通知を対象に、ロキの独立した転送経路を追加した。HEALBE通知の文面をそのまま表示し、ロキ独自の脱水判定・飲水量の計算はしない。

- 発行から5分以内の通知のみ。同じ内容は10分以内に再転送しない。
- 質問を上書きせず追加し、ID単位で受領。保留中の質問から独立して通知を取り出せる。
- Codexの点灯・画面復帰・終了後の復元処理を共用。HEALBEとCodexの表示済みIDは別管理。
- 会話・録音・ナビ中は割り込まず保留通知へ。静かな時間は読み上げ設定に従う。
- 通知受信のための追加ポーリングや常時点灯は追加しない。通常の同期、電源、通信、アプリ稼働は必要。

## 確認結果

- スマホの通知アクセス許可あり。
- 隔離Android検査299項目成功。うち水分通知分類・重複・鮮度・保留質問の保持・ID受領・Codex互換23項目、運動判定156項目、描画120項目。
- スマホv298 / グラスv691に適用。両端末とも署名一致・更新前データのバックアップ読取・インストール後ハッシュ照合済み。
- 合成の水分通知1件で、グラスがAsleep→通知だけでAwake・ロキ前面表示→表示終了・会話フラグ解除→Asleepに戻る実機試験に成功。表示済みID一致、スマホ受領、既存の待機操作4件の保持を確認。
- PCからの送信開始から表示確認まで約5.3秒。消灯後の手動点灯0、試験中のアプリ再起動0。
- 最初の送信試行はPCのPowerShell5の文字コードエラーで送信前に停止した。BOM付きUTF-8へ修正し、実送信は成功した1件。
- 実測はUSB接続中の画面スリープからの復帰であり、長時間の深い省電力状態・アプリ強制停止・通信断の保証にはしない。
- 合成通知で転送・点灯を検査した。次の実際のHEALBE水分通知が発生するまで、GoBe Uからの自然発火を含む全行程は未確認。

## エネルギーバランス

数値の常時取得は今回未対応。端末には旧GoBe補助アプリが残っており、ローカルソース上では数値取得時にHEALBE画面を開くフォールバックを持つ。現在のロキの歩数取得経路からは呼ばれていない。勝手に公式アプリを開いたり、画面を定期取得する動作は追加していない。HEALBEのエネルギー収支を、Health Connectの活動消費カロリーだけから再現した値で置き換えない。
