# KEEP開始直後の撮影失敗：v766修正と検証待ち

2026年11月26日。ユーザーの再試験でv765も保存0枚で停止。診断の根本例外はKeepCameraSession.onCaptureFailed由来のIOException「KEEP frame failed」。

## 実機ログで確認したこと

13:38:05のKEEP開始では、JPEGセッション構成は成功。その後13:38:07〜09に端末のCamX MfsrPrefilter処理でGeoLib計算・メタデータ・バッファの失敗が発生し、CaptureFailureが通知された。ログはカメラタグだけを抽出し、写真内容や会話は取得していない。

CameraCharacteristicsの公開情報では、org.codeaurora.qcamera3.sessionParameters.enableMFNRの既定値が1。対応するセッションキー805e0002もavailableSessionKeysに含まれていた。これをKEEPのセッションに限って無効化する設定が可能と確認した。システム全体や他アプリの設定は変更しない。

## v766の変更

- JPEG要求のテンプレートとcapture intentを単純なPREVIEW要求へ変更。JPEG出力のみで、プレビュー画面や連続繰り返し撮影は追加しない。
- 公開対応しているキーに限ってZSLをオフ、ノイズ軽減と輪郭処理をFASTへ設定。JPEG解像度上限1920×1080と圧縮品質85は維持するが、合成を避けるため暗所ノイズ等の見え方は変わる可能性がある。
- API28以降のSessionConfigurationで、広告されたMFNRセッションキーを整数0に設定。未対応のキーを作って送ることはせず、対応キーの列挙に存在する場合だけ設定する。
- 各Imageを閉じた後に次の要求が実行されるよう、撮影要求を同じカメラHandlerへポストする。前の要求とバッファの処理が重なる経路を避ける。
- CaptureFailureの理由・フレーム番号・画像生成有無を技術診断に記録する。優先譲渡による正常なフラッシュは取り消し扱い。
