# 予定登録前の照会失敗・終日区分の検証（スマホv221）

スマホv221へ反映しました。グラスはv574のままです。既存の未コミット変更を保持し、GitHubへのpushは行っていません。

## 修正

CalendarWriterの完全一致による重複防止は既存です。今回、既存予定の照会がnullを返した場合も「重複なし」として登録へ進む経路を修正しました。照会できなければ登録せず、確認できない旨を返します。複数予定の途中で照会に失敗しても、全件の事前照会が終わるまで登録バッチを実行しないため、新規登録は行いません。

重複判定は、指定カレンダー・予定名・開始・終了に加えて終日区分も一致を要求します。同じ依頼内の重複排除も同じ基準です。終日と時刻指定を、タイトルと時刻が同じというだけで片方へまとめません。登録後の読み返しでも終日区分を検証し、一致しなければ保存結果未確認として扱います。読み返し失敗時点では登録済みの可能性があるため、成功扱いや自動再送はしません。

- 既存回帰381項目成功。
- スマホv221実機44項目成功。これは周辺の依頼受付・参照・保存・診断の回帰検査で、実カレンダーへの登録試験ではありません。
- ビルド成功。会話プロンプト保護2区間の基準検査成功。プロンプト変更・新しいモデル送信はありません。
- 対象機種・署名を照合。更新前APKとアプリデータのバックアップを読み取り検証し、端末とPCのSHA-256一致、反映済みAPKのSHA-256一致を確認。

実際の予定登録・変更・削除は行っていません。追加のAI送信・経路検索・撮影・録音もありません。曖昧な予定名を照合して「既存更新／新規」を選ぶ機能ではなく、完全一致による既存対策の堅牢化です。通知の割り込み制御は調査しましたが、今回は変更していません。

スマホのロック解除後、共通確認・会話参照・録音確認の3画面と、グラスの新しい状態の受信を確認しました。v221の起動時ローカル検査も合格。検証用アプリは両端末から削除し、ロキ本体を起動しています。
