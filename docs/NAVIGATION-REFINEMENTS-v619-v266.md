# ナビ調整：メガネv619・スマホv266

2026年10月23日。実装・隔離検証・両端末への適用が完了。署名・バックアップ・インストール後APKを照合し、起動前にスマホ146ファイル、メガネ410ファイルの内容が維持されていることを確認した。

## 変更した6項目

1. **歩く速さに応じた通知距離**：速度を取得できる徒歩案内では、予告を60～120m、接近案内を22～45m、直前案内を8～15mの範囲で調整する。速度が不明・範囲外なら従来の120m・35m・12mを維持する。実際に歩いた測定に基づく最適値の確定は未実施。
2. **「もう一回」の対象を区別**：直近5分以内のAI回答とナビ発話の時刻を比較し、直前の対象へ向ける。AI回答は保存済みの文章を読み直し、再度Geminiへ質問しない。判断材料がなければ「回答かナビか」を聞き返し、直後の「回答」「ナビ」でも選べる。「次の案内」はナビを明示する操作として維持する。
3. **到着予想が変わったことと分かる理由**：残り時間の単純比較ではなく到着予想時刻を比較し、約2分以上の変化を表示する。経路再取得など確認できる変化を添え、情報がなければ「原因は取得できていません」と伝える。渋滞・列車遅延・乗り換え待ちの原因を推測で付け足さない。同じ経路での通知は2分以上間隔を空け、一時停止時の古い通知を消す。
4. **分岐表示を強調**：位置を確認でき、45m以内の分岐では矢印・距離を先頭へ出して拡大する。回答表示中や回答音声の再生中は、分岐強調行を重ねて追加しない。実機での移動中の視認性は未確認。
5. **認識失敗後の復帰**：認識エラーや空の認識結果で、保留中の変更確認を解除し、最新の位置と案内が確認できればナビの読み上げへ戻す。古い曲がり角の音声は再生しない。位置が未確認の場合は方向案内を保留する。
6. **変更確認をメガネで操作**：「その前にコンビニ」「やっぱり〇〇駅に行きたい」→「はい」→メガネで住所・場所候補を選択→経路を選択→内容を確認して「この経路で開始」。スマホは接続したまま裏側で検索・経路処理を行う。スマホを操作せずに選べるが、スマホとの接続・位置情報・経路API設定は必要。

## 変更確認の保持と取消

候補はスマホのメモリ内に最大5件、経路は既存の最大3件を保持する。確認セッションは3分以内で、開始済みセッション、別の目的地・移動手段・経路時刻、時刻の巻き戻り、古い位置、検索時点から200mを超える移動では確定しない。開始要求は同じセッションで二重に実行しない。

候補確認中は「キャンセル」で取り消せる。別の質問へ移った場合やナビ表示終了後も、古い取得結果の画面を新たに出さない。最後の開始確認はキャンセル側へ最初のフォーカスを置く。

## 検証結果と範囲

- スマホ・メガネの両APKがコンパイル成功。メガネ20区間・スマホ2区間の保護対象は維持。
- 実際の候補APKのクラスを別UID・権限なしのAndroid環境で実行し、1,292件が成功（今回追加76件）。
- 歩行速度の有無と上下限、従来の通知動作、聞き直し先・時刻の異常、到着予想時刻の比較、通知理由の情報不足、経路変更・一時停止、候補期限・二重確定防止を確認。
- 隔離テスト用アプリと入力ファイルは削除済み。検証から外部AI送信・経路検索・録音・音声再生は行っていない。
- 実際の移動、騒音下の発話、通知が聞こえるまでの時間、実経路での候補選択・開始完了は未確認。実装済みであることと、屋外で使い勝手が確認できたことを区別する。

## 次の実機確認

普段使う徒歩経路で、予告・接近・直前の3段階が「早い／ちょうどよい／遅い」のどれに感じるか確認する。続けて、直前の回答を聞いた後と道案内を聞いた後で「もう一回」を試す。場所を変更する場合はメガネで候補・経路まで進め、まずキャンセルで元の経路が維持されることを確認する。実際に変更したいときだけ開始する。

この実移動の結果を受けて、速度に応じた通知距離と割り込みからの復帰時間をさらに調整する。
