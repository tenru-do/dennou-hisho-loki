# 会話の継続・話題変更と回答出力枠（v578）

「年間では？」などの省略質問は前の条件を引き継ぐ。一方、「別の話。さっきの質問とは関係ないけど…」は明示的な話題変更を優先する。「話題を変えないで」「会話をリセットしないで」は変更の否定として扱い、「ところで、さっきの質問…」は継続する。「鍵を忘れた」などの日常の忘れ物を会話履歴への苦情と誤認しない。引き継ぎカード・追加質問・提案継続の判定で同じ境界処理を使う。これは明示表現の判定であり、すべての言い換えを理解できる保証ではない。

実APIの初回3件では文脈の受け渡しは意図通りだったが、提案1件がMAX_TOKENSで途中終了した（完了2/3）。Gemini 2.5 Flashの通常テキスト会話では思考と回答が出力上限を共有するため、通常会話のmaxOutputTokensを最低3072、thinkingBudgetを512に設定する。既に大きい出力上限は下げない。画像付きリクエスト・他モデルの設定は変更しない。思考予算はモデルへの指針であり、任意の長文が必ず完了する保証ではない。出力量・料金・遅延は実応答により変わる。

公式仕様: https://ai.google.dev/gemini-api/docs/generate-content/thinking?hl=en

## 検証

- ローカルの既存回帰と新規ケース518項目、既存の会話継続25項目が成功。
- 許可された初回3件と、別途許可された修正後3件だけを各1回送信。自動再送なし。初回は2/3完了、修正後は3/3がSTOPで完了。省略された年額（2,880,000円）、訂正後の端末A/Bの使い分け、明示的新話題（7×8=56）を確認。
- 実機のMainActivityのcompact prompt builderと通常カスタム設定を使い、変更したポリシークラスを先にロードして検証。通常の固定system rules、日時、personaを含めた。検索・ツール・動的共有記憶・外部会話・画像・音声を添付しない、許可範囲の検証専用経路。通常の関数実行や全API経路の試験とは区別する。
- 合成履歴は独立した設定名・ファイル領域を使用。実履歴は書き換えず、前後一致を確認。カスタム設定は検証後に隔離領域から削除。キー・設定全文・送信本文は結果へ保存しない。結果ファイルは合成応答と使用量のみ。
- 実API確認が成功した変更4区間だけprompt baselineを更新し、新規の境界・予算クラスも保護対象に追加。通常ビルドの18保護区間検査・コンパイル・APK検査が成功。
