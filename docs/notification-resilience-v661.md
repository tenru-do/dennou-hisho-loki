# 途中停止の調査・再発防止（2026-10-26）

## 確認できた原因と区別

1. **PC通知監視が停止していた**：復旧前にプロセスなし・ログイン時の起動なしを確認。元のプロセスが終了した直接原因は記録がなく未確定です。直近3日の該当Windowsアプリクラッシュ記録は見つかりませんでした。電源イベントはありますが、それだけで停止原因とは断定しません。
2. **監視が動いていてもログの途中書き込みを取りこぼす**：従来方式は未完JSONを読んだ時点でファイル末尾へ進め、後半が追記されても復元できません。同じ合成イベントで従来0件・修正版1件を再現しました。
3. **グラスの「会話中」フラグが残り通知を保留する**：AI・音声処理が動いておらず、画面も空なのにconversationActive=trueを確認。最終通常会話は約4.5時間前でした。通知の一度きりの18秒後処理が、処理番号や表示文字列の変更で解除を逃す経路を修正しました。修正版はv661です。
4. **USB認識は別問題**：低残量12%の確認後にグラスがADBから消えました。接続し直したとの返信後もスマホのみ認識され、WindowsにUSB記述子エラーがありました。未識別デバイスを確実にグラスと紐付けられたわけではありません。最後の取得ではUSB給電あり・電池状態dischargingでした。これだけで電池やケーブルの故障とは断定しません。

## PC側の対策（適用済み）

- LFで完結したJSONだけを処理し、途中のUTF-8とJSONは追記を待つ。
- ファイル読み取りは1回4MiBまで。巨大な単一レコードは明示記録し、次の改行まで読み飛ばして監視全体の停止を避ける。
- 通知の送信待ちを原子的に保存してから処理位置を保存。再起動時は同じ通知IDで再開し、5分超の通知は読み上げない。
- ログ差し替えを直前64バイトの指紋で検知。読み取りエラーは対象ごとに再試行し、他のセッションを止めない。
- 破損した保存状態を空で上書きせず、保存済みバックアップを参照。復元で不明になる情報まで完全に復旧できる保証はありません。
- 子監視の死活・進行時刻を親が監督。子が終了すれば再起動し、180秒進行がなければ、自分が起動した子だけを再起動する。
- 親の停止にはWindowsタスクのログイン起動・1分間隔の復帰確認・異常終了再試行を設定。現在ユーザーの限定権限だけを使用する。
- プロセス開始・終了・復旧の履歴を端末内ファイルへ保存。新しいログには通知本文・認証情報・接続先を残さない。
- 古い質問や操作は自動承認・削除・再送しない。

## v661の対策（ビルド・検証済み、端末適用はUSB待ち）

通知専用の表示番号で最新の通知だけを管理。空画面または同じ通知が残っていて、AI・録音・読み上げ・入力などが動いていなければ会話中フラグを解除します。実作業中なら待ち直し、別の回答を消さず、古い通知が新しい表示を解除しないようにしました。会話プロンプトや外部AIへの入力は変更していません。
