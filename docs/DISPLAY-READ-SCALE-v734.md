# 表示・READ保存・人物倍率の調整（グラス v734）

ナビの現在地表示で移動状況が案内文と同じ大きさになり、折り返して他の情報を押し出す問題を修正。現在の区間・移動だけを9dpの独立した1行にし、長い内容は末尾省略する。元の行数予算に含め、乗降・曲がり角の指示は通常の案内欄へ残す。停止・到着・現在地のみの表示では、この行も消去する。

READの撮影原本は従来から保存対象だったが、保存・撮影情報の取得失敗で回答処理まで中断する経路があった。撮影ごとの保存結果を分け、原本の保存失敗でも解析を続け、画面には実際の保存結果を表示する。AIの再試行で同じ撮影を重複保存しない。追加のREAD保存のために既存の写真を容量整理で削除しない。

READ転送待ちは自動転送とKEEP／PCからの明示取り込みで共通の処理を使う。写真ID・ハッシュ・サイズ・ギャラリー保存の受領記録を照合し、転送待ちを解除する。処理中のグラス原本は保持し、スマホ側の削除状態を優先する。保存・転送・ギャラリー保存を混同した成功表示は行わない。

人物は通常の立位画像（pose 4）と同じ見かけの目間距離を基準に、座位・寝姿・動作の倍率を校正する。元画像の横幅や余白、足の位置によって個別に縮小せず、顔を中央へ、頭頂を画面内へ配置する。手足が大きく広がる部分は表示範囲で切り取る。元画像と顔・体格そのものは変更しない。姿勢や表情の変化で倍率が揺れないよう、動作画像群の中では共通の基準を使う。

接触スワイプや近寄る演出の後にも頭頂を保護する。親の描画座標や左右反転を考慮し、必要な縦方向の移動だけを補正する。回転・倍率と反応の状態は保ち、描画中に毎回オブジェクトを生成しない。

## 検証方法

- `NavigationMovementLineChecks`：Androidの実TextViewとCanvasで、小さい1行・長文省略・文字の上下欠け・案内欄の高さを検査。
- `ReadPhotoCaptureTest`／`ReadPhotoTransferTest`：合成JPEG、暗号化、保存容量不足、撮影情報欠落、再試行、受領記録不一致と原本保持を検査。
- `ReadPhotoCaptureChecks`：隔離されたAndroidアプリ内の合成JPEGで保存・転送処理を検査。
- `CharacterViewportScaleTest` と既存の描画・姿勢回帰テスト：立位基準の倍率、顔中央、頭頂優先、透明余白・デコードサイズの不変性を検査。
- `CharacterScaleCanvasChecks`：候補APKの実描画、代表姿勢、接触スワイプ・反転・親座標・近寄り演出での頭頂保持を検査。

テストでは実際の撮影・録音・経路検索・外部AIへの送信を行わない。合成データでの保存／受領検査は、実カメラ撮影やその場の外部サービス利用の検証とは区別する。
