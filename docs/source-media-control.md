# 再生元Android端末の30秒送り・戻し

グラスのSET → 音楽・ラジオ：30秒送り・戻し → 接続端末のアプリ、から再生アプリを選びます。BluetoothのAVRCPではなく、接続端末のAndroid MediaSessionへ位置変更を要求します。

再生元のスマホ／Androidタブレットにはロキのスマホ用アプリが必要です。設定 → 接続・音声・読み上げ → この端末の音楽・ラジオ、からも使えます。通知へのアクセスは利用者がAndroidの設定で許可します。ブラウザ版ロキだけでは、そのタブレット自身の再生アプリを操作できません。

グラスは現在ペアリングしている接続先を操作します。Bluetooth音声の再生元を自動判別して端末を切り替える機能ではありません。タブレットを操作する場合は、そのタブレットのロキとの接続設定が必要です。

## 対応判定

アプリが位置変更を許可し、再生位置・長さ・通常速度を確認できる場合だけ操作します。アプリ名だけでは対応を保証しません。ライブ放送、広告、読み込み中などは非対応になる場合があります。radikoのライブ放送の現在より先へは進めません。タイムフリー等の外部操作対応は実機検証が必要です。

曲や番組が切り替わった場合は選び直します。先頭・末尾で移動できる時間が短い場合は実際の移動秒数を表示します。位置変更後の通知を確認できなければ成功と表示しません。同じ要求の通信再送で二重に移動しないよう、送信前に操作IDを保存します。通信エラー後は再生元で位置を確認してから次の操作を行ってください。

## 検証範囲

合成セッションで送り・戻し、先頭・末尾、曲変更、非対応状態、未確認応答、同じ要求の再送を検証しています。実アプリおよびAndroidタブレットでの結果は、各端末の検証記録に従います。広告・ライブなど各再生状態の網羅的な確認は未完了です。

## 実機確認（v640／v288）

スマホのradikoタイムフリー・YouTube Musicと、Android 13タブレット（21051182G）の通常YouTube・radikoタイムフリーで、30秒送り・戻しと変更後の位置を確認しました。タブレットのYouTube Musicは今回の対象ではありません。

radikoでは送り・戻しの直後に読み込み中となる場合があります。再生が戻ってから次の操作を行います。同じアプリが複数の再生セッションとして表示される場合があり、検証ではAndroidが優先する先頭の対応セッションを使用しました。端末によっては通常YouTubeが `com.google.android.youtube` と表示されます。

グラス上の隔離検査でも、本番の通信ソースを使ってタブレットのradikoへ送り・戻しを要求し、位置変化を確認しました。普段のアプリの接続先はスマホのまま保持しています。通常のグラスメニューからタブレットを使う場合は、接続先をタブレットのロキへ設定する必要があります。接続先を切り替える操作自体の検証や、Bluetooth音声の出力先の切り替えを行った結果ではありません。

## グラスv646のTOP操作

TOPのBT30は、押すだけで現在接続しているAndroid端末の優先される操作可能な再生セッションを30秒先へ送ります。アプリ選択画面は挟みません。アプリを選ぶ操作や30秒戻しは、SETの「音楽・ラジオ：30秒送り・戻し」から開けます。接続不可・対応セッションなし・操作結果未確認の場合は理由を表示し、自動再送はしません。スマホとタブレットの両方を同時に探索する機能ではなく、既存の接続先を使用します。
