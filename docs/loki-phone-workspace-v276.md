# スマホUIの整理（v276）

## 4つの入口

| 画面 | 主な用途 |
|---|---|
| 会話 | 質問の入力、送信状況、回答の停止、添付、会話履歴 |
| ナビ | 目的地・移動手段の指定、ナビ開始、メガネ表示、保存ルート、案内中の操作 |
| 記録 | 要対応の依頼、受信箱、保存済みメモ・回答、検索、写真・録音・生成画像 |
| 設定 | テザリング・共有、Bluetooth・読み上げ、TOPIC、更新・バックアップ、API設定 |

従来は「添付・その他」の高さが限られた領域にナビ・記録・設定まで入っていました。今回それぞれに全画面の表示領域を用意し、タブから直接開く構成へ変更しました。会話の入力欄は上部に残し、添付だけを会話内で展開します。

ナビは目的地・移動手段・開始ボタンを先に表示し、「よく使うルート」「案内中の操作・状態」「通知・省電力・応答時間」「保存経路・出口・駐輪場所」などは用途ごとの見出しから展開します。HUDという表現は「メガネの案内表示」に変更しました。

各タブは表示を切り替えるだけで、入力欄の作り直しや送信・経路検索を行いません。入力済みの文章・選択範囲・目的地・スクロール位置を保持します。記録からメモや参照セットを入力へ戻す際は会話画面を開きます。

既存の各操作の処理・認証設定・個人情報の初期登録は変更していません。個人の地点をソースやAPKへ追加していません。

## 検証・適用

最終APKの回帰検証は合計3,511項目成功。今回の画面切り替え検証は609項目で、100回の切り替えで文章・選択範囲・目的地を保持し、切り替えによる操作発火がないこと、スクロール位置を保持することを確認しました。

スマホv276へ適用済み。署名・バックアップ・インストール済みハッシュを照合し、起動前の既存147ファイルの内容保持を確認しました。メガネはv630のままです。

実画面で4タブの切り替え、選択色、ナビの4移動手段と開始ボタン、記録・設定の用途別表示、設定の展開、会話内の添付欄開閉、キーボード表示時の入力・送信ボタンの視認性を確認しました。最後は添付を閉じた会話画面へ戻しています。取得したアプリログ範囲にクラッシュはありません。

実機確認では質問・写真の送信、経路検索・案内開始、API設定の保存は行っていません。
