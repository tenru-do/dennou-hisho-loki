# NAVI通信・更新優先の改善 — メガネv628・スマホv275

## 実装した5項目

1. 同じ証明書のTLSソケットファクトリーを最大4件まで再利用します。証明書の固定確認・期限確認・トークン認証は保持します。HTTP応答後にスマホ側が接続を閉じるため、TCP接続を常時保持する変更ではありません。
2. 経路線は識別子で照合し、変更時・キャッシュ欠落時だけ本体を送ります。同じ経路では現在地・距離・次の案内などを更新します。経路・目的地・区間・世代が変わると全体を送ります。旧版との組み合わせには従来形式を使います。各端末の経路キャッシュは1スナップショットです。
3. 徒歩・自転車・車で、近い分岐は約750ms、通常約2秒、遠い直線約3秒を目安に問い合わせます。復帰・位置未確認は約1.5秒、公共交通は通常約2秒、非案内中は約8秒。通信中は重複要求しません。GPS自体の取得間隔は変えていないため、750msごとに新しい位置が得られるわけではありません。車の独自読み上げ対応は変更しません。
4. 表示時の位置情報の古さを下限・上限で計測します。スマホ側の経過時間にメガネでの受信後の時間を加え、片道時間が不明な分は通信往復を幅にします。端末間の時計を直接引き算せず、住所・経路・会話・キーを計測履歴へ保存しません。実描画完了や音が出る時刻ではなく、実案内の値は利用者が案内を開始した後に確認する必要があります。
5. 短い徒歩経路で、通知、通過後、連続分岐、停止・再出発、画面復帰、自然なGPS復帰を確認する手順を用意しました。操作は立ち止まって行い、案内開始は利用者が選びます。

## 検証

回帰2,805項目＋移動手段別67ケース、合計2,872項目が成功しました。

- 512点の合成経路：全体16,141バイト→同じ経路の更新297バイト。実経路のデータ量は異なります。
- 差分往復1,000回、内容破損、目的地・世代変更、キャッシュ欠落、旧版形式、座標数値の表現差を確認。元オブジェクトは変更しません。
- TLS準備の再利用と、別証明書の分離、位置情報の経過時間の下限/上限を確認しました。
- 6時間分の仮想トレースと実時間2分の連続負荷を再検証しました。実際の6時間の移動・録音・再生ではありません。

## 通信専用の実測

変更前：中央値297.9ms、最大532.8ms（5件）。
変更後：中央値399.0ms、最大509.4ms（5件）。

更新前後の5回比較では遅くなり、短縮は確認できませんでした。追加の交互比較10組では、毎回TLS準備を作る条件の中央値305.1ms、再利用条件263.0msで、再利用が速かったのは7/10組です。少数かつ通信環境を制御していないため、安定した改善の証明ではありません。

同じ端末と通信専用の小さな応答による別時点の5回ずつの標本です。Wi-Fi・端末負荷は制御していないため、常時の速さや改善率は断定しません。経路計算・GPS・音声を含む全体の遅延ではなく、経路線削減の合成検証とも区別します。

## 適用状況

スマホv275・メガネv628とも適用済み。バックアップ・署名・インストール済みハッシュ・更新直後の既存ファイル保持を照合しています。外部APIへの新規検索は0回、個人の地点の初期登録と実案内開始はしていません。実移動と実音声併用は未検証です。
