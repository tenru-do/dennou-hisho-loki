# Codex通知の表示直前判定（グラスv575）

## 修正

従来はスマホへ受信確定を返してから画面処理を予約し、その間に会話が始まると通知を表示せず終了していました。今回、画面スレッドの最終判定結果が出てから受信確定／保留をスマホへ返す順序に変更しました。

最終判定では、前面表示、終了状態、ナビ優先、会話処理、連続音声モード・録音・音声認識、朝の再生、口の動き、ユーザー依頼待ち、下書き入力、TOPICの読み上げを確認します。いずれかが使用中なら重複処理済みIDを更新せず、既存のスマホキューで保留します。

最終判定で通知の発行時刻を再確認し、5分を超えた古い通知を読み上げません。重複IDも読み上げません。画面スレッドへの待機は最大2秒で、待機中のままタイムアウトしたコールバックは後から表示できないよう取り消します。表示処理がすでに開始した場合は、その結果に応じて既存IDの重複抑止を使います。メインスレッドでネットワークの応答は待ちません。

通知の種類がquestion・statusの場合は、成功通知ではなくinfoとして表示します。表示処理の例外もメインスレッドから漏らしません。

## 検証範囲

ホスト回帰397項目成功。追加16項目で待機中の取消、開始後の完了、二重開始拒否、保留結果、期限境界、不正メタデータを検査しました。ビルドと会話プロンプト基準16区間の検査も成功。プロンプトを変更せず、AIへの追加送信はありません。

実機では合成データと隔離設定を使用します。通知の待機判定・期限切れ・重複を、実際に読み上げず検証します。実際の受信通知を消すテストや、予定登録・撮影・録音は行いません。

これは全通知を保存する新しい受信箱ではなく、既存Codex通知経路の改善です。一般のLOKI_ALERT通知の方式は変更していません。期限切れ通知の一覧機能も追加していません。継続するVOICEやナビ中は、5分以内に空きがなければその通知を読み上げません。表示したことはスピーカーで聞こえたことの保証ではなく、プロセス強制終了をまたぐ厳密な一度だけの配送を保証するものではありません。

既存未コミット変更を保持し、GitHubへのpushは行っていません。新しい権限、送信先、通知本文の保存先は追加していません。

## 反映後の結果

グラスv575を反映し、スマホはv221を維持しています。対象機種・署名一致、旧APKのハッシュと更新前バックアップの全メンバー読み取り、端末／PCのSHA-256、インストール済みAPKのSHA-256を確認済みです。

実機32項目成功（既存保存・転送18項目＋通知の判定・保留・期限切れ・重複14項目）。合成通知の表示や実音声の読み上げ試験は行っていません。通知待機を解除した後に実際に聞こえるか、装着状態での確認とは区別します。

グラスの起動時ローカル動作チェック合格。実際のグラスから状態同期を呼び出し、スマホの暗号化状態ファイルが直近15秒以内に更新されたことを確認しました（本文は読み出していません）。検証専用アプリと検証DEXをグラスから削除し、ロキ本体を起動しました。
