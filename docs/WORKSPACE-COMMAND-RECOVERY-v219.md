# 端末操作の再受付保護（スマホv219）

スマホv219へ反映。グラスはv574のままです。既存の未コミット変更は保持し、GitHubへpushしていません。

## 修正

「会話の参照先変更」「登録候補の訂正」の端末間コマンドについて、保存済みの未送信操作が期限切れの場合、同じIDの再受付でもキューへ再投入しません。現在の内容を確認して新しく操作するようエラーを表示します。すでにキューへ受付済みの同じIDは重複として返し、キューへ追加し直しません。これはカレンダーの登録そのものではなく、既存の登録前確認候補の訂正処理です。

同じIDの内容照合はJSONのキー順に依存しない構造比較に変更しました。配列内の順序や項目・値の変更は別内容として拒否します。元の保存データは比較によって書き換えません。操作IDはUUID形式を厳密に検査し、ハイフンのみなどの不正形式を拒否します。

## 検証

- 通常ビルド成功。会話プロンプト保護2区間の基準検査成功。会話プロンプトとモデルの送信形式は変更していません。
- ホスト回帰374項目成功。うち16項目はID、構造比較、配列順、型、期限と原データ保持の追加検査です。
- スマホv219実機40項目成功。暗号化保存した期限切れコマンドの再投入拒否、キュー非変更、期限保持、受付済みIDの重複処理、不正ID拒否を追加しました。合成データを隔離して使用し、予定登録・AI送信はありません。
- 更新前に機種、署名、旧APKのハッシュを照合。アプリデータのバックアップ全メンバーを読み取り、端末とPCのSHA-256一致を確認。インストール済みAPKとビルド成果物のSHA-256一致も確認しました。

今回の修正は明示的な端末操作の再受付処理です。自然言語の文脈理解や訂正発話のモデル品質を改善・検証したものではありません。すべての遠隔操作を永久に一度だけ実行できる保証でもありません。追加の外部送信、撮影、録音、新しい権限はありません。

実画面の共通確認・会話参照・録音確認の3画面と、グラスから新しい状態を受信できることを確認しました。スマホv219の起動時ローカル検査も合格。検証専用アプリは両端末から削除し、ロキ本体を起動しています。
