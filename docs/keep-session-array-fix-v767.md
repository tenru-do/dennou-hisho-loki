# KEEPのMFNR設定型修正：v767

2026年11月26日。v766のユーザー試験は撮影前にIllegalArgumentException「Not an array: class java.lang.Integer」で停止した。追加したベンダーMFNR設定値の型が原因で、修正側の誤り。

端末のavailableSessionKeysから取得するenableMFNRキーは、Androidフレームワーク上ではint[]型として扱われていた。整数0ではなくint[]{0}を渡すよう修正した。

## 適用前・適用後の実機確認

1. カメラ固有のベンダー識別子を持つ実メタデータを用い、CaptureRequestへint[]{0}を書き込み・読み戻す検査に合格。カメラは開いていない。
2. 完全ビルドと回帰検査、1,574件のセッション制御検査に合格。
3. 署名一致とインストール後APKハッシュ一致を確認してv766→v767へデータ保持更新。スマホv325は変更なし。
4. ロキを前面に開いた上で、インストール済みv767のKeepCameraSessionを同じアプリUIDから生成し、Camera2セッションの初期化・終了に合格。captureメソッドは一度も呼ばず、写真は撮影・保存していない。

v764/765の開始失敗はCamera2のCaptureFailureと端末MfsrPrefilterエラー。v766の失敗は上記設定型の誤りで、別の問題として区別する。v767での実JPEG保存成功、長時間撮影、容量増加の改善は依然ユーザー試験待ち。

新しいKEEP開始時は古い技術エラー記録をクリアし、開始時刻・最初の保存成功・新しい失敗を区別して記録する。画像・認証情報は診断へ保存しない。
