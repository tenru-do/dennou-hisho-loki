# v447 セキュリティ対策と移行手順

2026-10-10。グラス447、スマホ152、Audio Relay20のソース候補。既存の全身・顔表示、会話、KEEP、撮影間隔、5GB上限を維持する。実機更新・装着検証は未実施。

## 通信と接続の対策

- スマホの機能APIはTLS 1.2/1.3の8766番ポートへ移す。8765番は公開の証明書指紋と認証証明 `/tls-auth` だけを返し、旧API・ペアリング要求には426を返す。ここに会話・APIキー・連携トークンを送らない。
- 既存のランダム連携トークンで証明書SHA256のHMACを検証し、その証明書を固定したTLSで通信する。偽の証明書・偽の証明・期限切れ・リダイレクトを拒否し、平文へ戻らない。共有トークンを知る機器は同じ信頼グループとなる。
- 新規接続ではスマホ画面の証明書SHA256を相手側へ登録する。ネットワークから取得した指紋を無確認で信用しない。指紋は秘密ではない。
- ペアリングは60秒の一回限りの受付に加え、相手側の6桁コードをスマホ画面で照合して許可する。未許可・拒否・30秒以内に確認できなかった要求へトークンを渡さない。無効なコードや閉じた窓は拒否する。受付の時間は端末の時計変更に影響されない経過時間を使う。
- サーバーの同時処理・待ち行列・入力行・ヘッダーを制限する。ネットワーク上の妨害全般を防止する保証ではない。

## 保存データ

- 写真はAndroid Keystoreの非エクスポートAES鍵でAES-GCM暗号化し、`.jpg.gcm` に保存する。改ざんや別の鍵では復号できない。5GBは暗号化後の実バイト数で管理する。
- 起動時に旧JPEGを一枚ずつ暗号化する。書き込み・保護マーカー引継ぎ・既存コピー検証を終えてから元JPEGを削除する。空き容量不足や失敗では元写真を残す。移行と撮影・書き出しは同じアーカイブのロックで直列化する。
- KEEPの前2分・後1分と、保護済みを自動削除しない規則を維持する。写真のファイル名・時刻・保護マーカーは暗号化対象ではない。保護写真の無期限保存も変更しない。
- RECの「記録写真を復号して共有」で必要な写真をJPEGとして書き出せる。共有先を利用者が選ぶ。アプリ内部キャッシュに最大1時間有効なJPEGを置き、URI読取り権限だけを渡す。期限後は読取りを拒否し、次回起動・REC操作・遅延処理でキャッシュを削除する。共有先が保存したコピーはロキから消せない。
- Keystore鍵は端末から書き出さないため、暗号化ファイルをPCへコピーしただけでは別端末で復号できない。アプリのデータ消去・アンインストール前に必要な写真を共有して保存する。更新は既存署名のまま `install -r` を使う。
- 反応監査の会話ハッシュを端末内秘密鍵のHMACへ変更する。旧無塩ハッシュの診断ログは初回の監査書込み時に消去する。会話履歴は消去しない。感情・時刻は依然として機微情報であり、完全匿名化ではない。反応分類のLogcat出力は開発ビルドだけに限定する。
- カメラAMBで画像がGeminiへ送られることを初回開始前に表示し、同意後に開始する。REC単独は写真を送らない。

## ビルド・署名

通常の統合ビルドはデバッグ無効で、既存端末と署名を合わせるため従来のローカル統合用鍵を使う。これは新規の一般配布用署名を確立したという意味ではない。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build-integration.ps1 -App glass
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build-integration.ps1 -App phone
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build-integration.ps1 -App audio-relay
# バックアップ・計測のために必要な場合のみ明示的に選ぶ
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build-integration.ps1 -App glass -Development
```

一般配布用は `-Release -KeyStorePath <鍵のパス> -KeyAlias <alias>` と、環境変数 `LOKI_RELEASE_STORE_PASSWORD` / `LOKI_RELEASE_KEY_PASSWORD` を指定する。資格情報の欠落、`-Development` との同時指定はエラー。鍵やパスワードをソースへ登録しない。別署名への変更は既存アプリへ上書きできないので、インストール対象の署名を変えるためにアンインストールしない。

非デバッグAPKではADB `run-as` によるデータバックアップができなくなる。更新前に既存APK・アプリデータ・写真をバックアップできたことを確認する。暗号化後の写真だけのコピーを復元可能なバックアップと誤認しない。バックアップ方法を確認せずにアプリのデータ消去や署名変更を行わない。

## 更新順序と互換性

1. グラス・スマホ・必要ならAudio Relayの機器、アプリ名、版、署名を確認し、既存データをバックアップする。
2. グラス447とスマホ152を同じ更新作業で導入する。旧版と新版の組合せは通信できない。安全のため旧HTTPへ戻す互換機能は設けない。
3. 既存トークンがあれば証明書確認を自動で行う。初回の新規接続では、指紋登録後にスマホの60秒受付を開き直し、両画面の接続コードを確認する。
4. Audio Relayを使う機器も20へ更新する。PC側も同梱の `secure-bridge.ps1` を利用した新しいスクリプトへ更新する。
5. PCのUSB転送は `18765 -> 8765`（公開証明書確認）と `18766 -> 8766`（TLS）を使用する。トークンを使う要求は必ずTLS側へ送る。
6. 接続・会話・ナビ・TOPIC・AMB・音楽・明るさ・撮影・KEEP・共有を実機で確認する。初期化や古いAPKへの無条件上書きで問題を回避しない。

現在の未更新端末には今回の対策はまだ反映されていない。Gitの過去履歴や以前のバックアップ・旧APKも変更していない。

## 検証

再実行: `powershell -NoProfile -ExecutionPolicy Bypass -File tools/test-bridge-security.ps1`。Windows PowerShell 5.1で実施済み。グラス84・スマホ66・Audio Relay6ソースは errors=0 / warnings=0 でビルドし、APKの署名とデバッグ無効を確認した。顔・全身の意味判定の回帰試験も通過した。

ホストで正しい／誤った証明書の実TLSハンドシェイク、証明書HMACの検証・改ざん拒否、PCの実TLS通信、公開証明書確認にトークンが混ざらないこと、暗号化写真の復号・改ざん・別鍵の拒否・nonce変化・旧写真とKEEPの移行・移行の再実行・容量計算を検証した。既存の削除順・保護・満杯時停止・音声コマンド除外の回帰試験も通過した。ペアリング窓は24並行要求の一回受付を検証した。

Android Keystore上でのTLSサーバー動作、実機間通信、確認ダイアログ、写真移行と共有、装着時の動作・速度は端末接続後の最終検証が必要。一般配布署名の検証は配布用鍵が指定された段階で行う。
