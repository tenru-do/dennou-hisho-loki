# ナビの休憩・到着確認・診断：メガネv613・スマホv262

スマホの入口は「添付・その他」→「ナビ」→「ナビの休憩・到着確認・診断」です。

## 追加した6項目

### 1. 一時停止と再開

ロキのナビを一時停止し、再開時に現在地から経路を取り直します。公共交通は現在時刻から候補を選び直します。取得・選択が済むまで古い案内を読み上げません。

停止した目的地と入力中の目的地が異なる場合は、再開や乗り遅れ検索を止めて確認を求めます。停止状態は端末内に暗号化して保持し、再起動後も自動再開しません。24時間より古い停止記録では目的地を選び直す必要があります。再開・終了・新しいナビ開始で停止記録を解除します。

メガネのナビメニューからも停止・再開できます。Googleマップ自身の音声や、別アプリの案内を止める設定ではありません。

### 2. 乗り遅れ時の候補選択

「乗れなかった・次の候補を探す」でロキの案内を一時停止し、現在地・現在時刻から公共交通の候補を取り直します。NAVITIMEの保存済みの日時指定は、この操作では使いません。

候補を選び、区間を確認して「この経路で開始」を選ぶまで別の便へ切り替えません。取消時は一時停止を保持します。乗車済みの区間では、降車後の操作を案内します。実際の運行・空席・遅延を確認したとみなす機能ではありません。

### 3. 階段回避の希望

「階段回避の希望」を追加しました。既定は希望未設定です。次回の候補検索から適用します。

- NAVITIMEの公共交通検索と対応する形状取得には、階段回避の指定 `walk_route=avoid_step` を渡します。契約・利用中のAPIサービスでの対応と、現地に階段がないことは未確認です。
- Google Routesや他の経路では、同等の階段回避として扱えることを確認できないため「対応未確認」と表示します。屋内回避を階段回避に読み替えません。
- 利用中の選択経路を設定変更だけで勝手に差し替えません。設備の運休・故障・現地の通行状況は保証しません。

参照：[NAVITIMEのトータルナビ仕様](https://api-sdk.navitime.co.jp/api/specs/api_guide/route_transit.html)、[Google Routesの回避条件](https://developers.google.com/maps/documentation/routes/route-modifiers)。実装は公式の指定と区別して、利用中のサービスでの実通信確認が未実施であることを明示します。

### 4. 経路を順番に確認

スマホから取得済み経路の区間順を確認できます。公共交通の候補選択後は、スマホ・メガネとも出発前の確認画面を挟みます。徒歩・公共交通・駅名・路線名は取得したデータを使い、不明な区間を補いません。

開始直前にも候補ID・目的地・移動手段・有効期限・階段回避設定を確認します。確認中に条件が変わった場合は候補を選び直します。経路が未取得なら、その旨を表示します。

### 5. 到着を確認して終了

既定を利用者の確認式にしました。目的地への接近が確認できると「目的地付近です」と表示し、「到着を確認して終了」でロキの案内を終了します。

「まだ到着していない」で確認を見送り、案内を継続できます。「到着確認の方法」から従来の自動終了にも変更できます。目的地が変わった後に古い到着確認で終了しないよう照合します。GoogleマップやSDK自身の終了動作は別です。

### 6. ナビ診断の記録

既定では保存しません。「診断の保存範囲」で次のいずれかを選べます。

- 保存しない
- 位置なしで記録
- 位置を含めて記録

範囲を選んだ後、「案内の不具合を記録」から、遅い・方向が違う・経路が違う・その他の印を付けます。その時点の位置更新の古さ・精度・経路更新中か・省電力中か・区間の種類などを保存します。座標は「位置を含めて記録」を選んだ場合だけです。

会話、目的地名、案内文、APIキーは診断記録に含めません。記録は暗号化し、100件を上限に24時間以内の記録を扱います。読出し時に期限切れを除去します。常時の移動履歴は保存しません。保存範囲を変更すると既存の診断記録を削除します。

「診断を表示・共有」では内容を確認してからAndroidの共有先を選べます。自動送信しません。メガネにも「案内が遅い・診断を記録」を追加しました。保存範囲が未設定なら記録しません。

## 検証と限界

- 会話処理の保護対象はメガネ20区間・スマホ2区間ともチェックに成功しています。
- 一時停止の暗号化と目的地照合、古い停止記録で自動再開しない制御、経路確認、階段回避パラメーター、到着待ち表示、診断の許可項目と件数上限を独立したAndroid環境で検証しました。最終検証は1,020件成功（今回追加61件）。APKハッシュは navigation-controls-v613-v262-validation.json に記録しています。
- 外部AIへの質問や、実際の経路検索は検証で実行していません。
- 実際の次便候補、階段回避経路、休憩後の歩行再開、現地での到着確認、音声の停止タイミングは未実測です。
- スマホ実機で操作メニュー、経路確認、階段回避の注意書き、到着確認の既定、診断の保存範囲と表示画面を確認しました。検索・保存・共有・設定変更は行っていません。
