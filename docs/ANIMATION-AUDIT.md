# 画像アニメーションの自動検品

現在の描画処理が作った連続PNGをPCで数値比較するメンテナンス用ツール。常駐アニメーションに検査処理を加えず、グラスの通常利用時のメモリ・CPU負荷は増やさない。元の画像・アプリ・会話は変更しない。

## 使用方法

Python、Pillow、NumPyと、Androidの開発用描画書き出しには既存のローカルAndroid SDK/JDKが必要。依存関係のネット取得はしない。

既存の描画結果を検査：

```powershell
./tools/Invoke-AnimationAudit.ps1 -Review "<manifest.jsonがある検品フォルダー>" -Output "<新しい結果フォルダー>"
```

接続中のグラスで書き出しから検査まで：

```powershell
./tools/Invoke-AnimationAudit.ps1 -Serial "<グラスのADBシリアル>" -Output "<新しい描画結果フォルダー>"
```

グラスのモデル、ソース版、インストール済みAPKのSHA-256一致を照合してから、明示時刻による既存のAndroid描画処理を実行する。全身は停止1、待機4、発話6、まばたき7、隣接IDへの人工的切替5コマ。顔は停止1、待機4、発話6、まばたき7コマ。静止基準の目・口の登録位置も書き出す。録音・撮影・外部API・ユーザー会話は使わない。検証APKのみを一時インストールし、完了後に削除する。ロキ本体のAPKは更新しない。

実際の会話反応のフレーム順を別途書き出す場合は `-Poses routes`。全身の隣接IDを使った人工切替と、本番の反応ポリシーのフレーム順は異なる。会話経路の全分岐、通信待ち、描画の実FPSや装着時の見え方まで再現するものではない。

USB切断で結果を回収できなかった場合は、`export-state.json` のrunを使う。端末内のmanifest完成後に次で回収する（未完了なら失敗し、成功扱いにしない）。

```powershell
python tools/motion-review/recover.py --serial "<グラス>" --run "<12桁のrun>" --output "<中断時の出力フォルダー>" --audit
```

## スマホを隔離描画ホストとして使用

```powershell
python tools/motion-review/export-host.py --serial "<Android 11以降の検証端末>" --output "<新しい出力>"
python tools/motion-review/audit.py --review "<その出力>" --output "<その出力>/auto-audit"
```

権限を持たない専用検証APKへ、PC上のグラス用APKと検品用dexをコピーし、コピー後もSHA-256を照合する。ロキのApplicationやActivityは起動せず、元APKの同じ描画クラス・アセットを隔離したAndroidのソフトウェアCanvasで使う。入力と出力は検証APKの専用領域へ保持し、完了後に検証APKと今回の一時入力を削除する。スマホのロキの設定・記録を読み書きしない。これはグラス実機での描画検証とは区別し、結果のhostにも記録する。Androidバージョンや描画実装差はあり得る。

## 検査内容

- PNG不足、破損、寸法違い、空描画：データエラー。
- 連続コマに変化なし：動作欠落の候補。
- 発話中の口領域、まばたき中の目領域の変化が弱い：局所動作の候補。輪郭重心で整数の平行移動だけを補正する。
- 同じ動作の輪郭高・中心の急変：縮尺・位置の跳ねの候補。
- 顔付近と胴体領域の画素重心の相対変化：顔と体のずれの候補。
- 目の間隔に対する目→口の登録位置：座標の不整合候補。
- 姿勢切替の隣接コマの大きな画素変化：切替を確認する候補。

`auto-audit/audit.html` で種類・ID・指摘で絞り込み、対象コマへの移動、再生・コマ送り、顔と首の拡大、登録位置の重ね表示、目視メモの保存ができる。`audit.json` にAPK・manifest・全PNGのハッシュと各測定値、`findings.csv` に候補一覧、`thresholds.json` にしきい値を残す。既存の描画コマと結果フォルダーを一緒に保管する。ブラウザの確認メモはAPK/manifestハッシュ別に保存し、JSONへ書き出せる。自動の候補と人による確認結果は別扱い。

しきい値の調整には `-Thresholds "<thresholds.json>"` を使い、新しい結果フォルダーへ再実行する。元の結果を上書きしない。

## 限界と検証

検出なしは自然な動きの合格ではない。人体や骨格を認識するAIではなく、余分な腕・首の解剖学的異常・表情の意図までは判定しない。登録領域は停止コマ基準なので、大きな移動・横顔・閉眼・手による遮蔽などでは誤検出・見逃しがある。呼吸のわずかな動きが検出されても、見た人が十分に自然と感じることは保証しない。APK更新・画像修正の判断は候補の目視確認後に行う。

```powershell
python tools/motion-review/test_audit.py
node tools/motion-review/test_ui.cjs "<合成検品レポート/audit.html>" "<画面PNG保存先>"
```

合成データ21テストで、静止した口・頭だけの移動・縮尺変化・不正座標・不足コマ・サイズ違い・安全な展開などを検証。Edgeの合成画面操作12項目と、全480系列の実データ画面10項目も外部リクエスト0件で検証。これらは検出ルールと画面の検証であり、人の自然さの評価精度を測定したものではない。


## 2026-10-20 の実行結果

グラスv596の更新済みAPKと同じSHA-256のAPKを、接続済みスマホの隔離Canvasホストで描画した。全身443・顔37系列、10,855 PNGを生成・検査し、書き出しエラー/不足/破損/寸法不一致は0件。通常のロキのデータ・設定や本体APKは変更していない。

一次検査で弱いまばたき候補42件が出たが、閉眼表情の登録状態との照合で検査対象を区別した。旧形式の書き出しへの補助情報は、同一ビルドの静的な目の開閉登録を読み出し、元APKハッシュと一致するJSONにして `--eye-state` で与えた（PNG・元manifestは変更しない）。補助JSON自体のSHA-256も報告へ保存した。新しい書き出しは開閉状態も同時に保存する。

最終的にはbody-237・247・425・430の4系列が顔領域の登録情報不足で未判定。476系列は今回のサンプル時刻・しきい値で候補なし。口・目の実描画や作画を自然さの基準で合格と認定したものではない。画面の拡大サンプルとして座位283の実PNGも目視した。

グラス実機上の全件書き出しも開始したが、USB切断が繰り返された。再接続後、描画が完了していた立位0・座位168・座位283の各23コマ、計69コマを回収した。PNGは実機の検品キャッシュから読み出し、登録位置と時刻表は同一APKの書き出しmanifestから補完したことを別途記録している。実機サンプル3系列の数値検査は候補0件。Android実装差による画素の違いもあったので、スマホとグラスの結果は同一と仮定せず分けて保管している。全件の実機描画は代表サンプルの回収後に終了し、今回のUUID付き一時キャッシュ・診断APK・dexを削除して通常起動を確認した。スマホ隔離ホストも削除済み。グラス実機上の全480系列や装着時の見え方を確認済みとは扱わない。
